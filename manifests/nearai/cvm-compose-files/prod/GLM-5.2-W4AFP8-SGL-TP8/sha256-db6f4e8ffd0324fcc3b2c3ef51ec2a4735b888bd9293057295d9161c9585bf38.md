## Cross-check synthesis

- **[X1 / CRITICAL — exposure, not capture] The engine's unauthenticated `/configure_logging` is reachable, and this document is why.** `external: true` shared network (366-369) + bare `location /` on the serving listeners (822-833, 918-929) + no `--admin-api-key` + a downstream pipeline that ships stdout verbatim off-box to two backends. ## Verdict

**Qualified PASS — with the same qualification as its sibling, and a larger blast radius.**

- **What this file configures:** clean. Every logging flag is literal and minimal; `--log-requests-level 0` is explicit; zero `${VAR}` in the engine command; no dump, crash, profile or trace flag; `--trust-remote-code` pinned by revision; `OHTTP_ENABLED=true` literal; telemetry destinations literal; **no KV or prompt disk cache**; the discovery stub is properly gated and fails closed. On the configured path, **no plaintext copy is written to any log, file, cache or network destination.**
- **What this file fails to contain:** the engine's own live paths. It leaves `/configure_logging` reachable by two independent routes, declines the one flag (`--admin-api-key`) that would gate it, sets the in-flight population that a watchdog dump would expose to 256 requests at up to 1M tokens, and guarantees that anything printed leaves the CVM unscrubbed — here, to two backends. **The invariant this layer delivers is "content capture is not configured", not "content capture cannot be enabled".**
- **Recommended, in order:** (1) pass `--admin-api-key` to the engine; (2) apply the `:8001` stub's own allowlist idiom to the serving blocks, or move the engine to a project-private network; (3) reconsider `--max-running-requests 256` at 1M context as the dump-exposure ceiling; (4) add a scrubbing/deny processor to `filter/app_logs` for engine-sourced records.
