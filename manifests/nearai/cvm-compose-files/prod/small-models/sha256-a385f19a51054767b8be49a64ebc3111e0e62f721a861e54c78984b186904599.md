## Check 3 — In-enclave `build:` services **[HIGH — supply chain]**

Three services are built at deploy time inside the enclave; for all three, part of what runs is resolved from **mutable external sources at build time**, so their code identity is *not* fixed by this file's hash — drift leaves no attestation-visible trace:

1. **`sglang-diffusion`** (FLUX, lines 152-161): `FROM lmsysorg/sglang@sha256:8ece90ad…` — digest-pinned base, but **that digest has no published review** (observed, not audited; the audited sglang digests are others). Then `RUN python3 -m pip install -e "python[diffusion]"` and `pip install accelerate einops` — the engine itself installs editable from in-image source (good), but the `[diffusion]` extra's dependency tree plus `accelerate`/`einops` resolve **unpinned from PyPI at whatever versions exist on build day**.
2. **`vllm-with-audio`** (whisper, lines 1174-1178): `FROM vllm/vllm-openai@sha256:ccd6a6db…` (audited base) then `RUN pip install openai-whisper torchaudio librosa vllm[audio]` — **`vllm[audio]` re-resolves vLLM from PyPI and can install a different vLLM version over the digest-pinned engine inside the enclave.** The base image's page states explicitly that whatever engine whisper runs, it has not audited it. The strongest instance of the pattern: the pinned digest is potentially cosmetic.
3. **`privacy-filter-hf`** (lines 243-252): `FROM pytorch/pytorch:2.5.1-cuda12.4-cudnn9-runtime` — **tag-pinned, not digest-pinned** (the registry can serve different bytes under this tag), plus unpinned `pip install "transformers>=4.46" accelerate fastapi "uvicorn[standard]"`. Counter-weight: this is the one service whose **entire application source is inline in the manifest** (`server.py`, lines 254-412) and therefore pinned by the file hash. That code handles full message text by design (it is the PII classifier); it contains **no print/log of text content** — its only stderr writes are numeric VRAM watchdog messages (lines 332-336) — and its HF pipeline pins `revision=7ffa9a04…` with `trust_remote_code=True` (316, 323; pinned, so inert against drift). Framework-level logging (uvicorn access logs, transformers warnings) is untraced here.

## Check 4 — Telemetry pipeline: stdout of every plaintext service leaves the box twice, unredacted **[HIGH — systemic, = C3]**

Chain, fully traced within the two documents: every app service logs via the `json-file` driver (anchor lines 1-6) → (a) the **measured** datadog-agent's `DD_LOGS_CONFIG_CONTAINER_COLLECT_ALL=true` ships every container's stdout/stderr to `us3.datadoghq.com`, and (b) **otelcol-contrib** (this file, lines 1387-1417; digest-pinned, [audited](/images/docker.io/otel/opentelemetry-collector-contrib/sha256-85ac41c2db88d0df9bd6145e608a3cb023f5d8443868adbfbbf66efb51087917.md)) tails `/var/lib/docker/containers/*/*-json.log` (1464) and its `filter/app_logs` (2021-2030) drops only management/telemetry containers — the **app** containers' logs (all engines, all proxies, nginx, registrar, dcgm, privacy-filter) ship to the literal `https://telemetry.infra.near.ai` (2058). **No processor in either pipeline redacts or scrubs content** — the processors are memory_limiter, resource tagging, metadata transform, filter (routing), groupby, batch (2073-2092). The guarantee "no content leaves" is exactly equivalent to "no plaintext service ever prints content" — the per-image source pages carry that weight (e.g. gpt-oss's engine page records a crash-path token-ID leak into this very pipe).

- **Topology:** joins the measured layer's flat bridge as `external: true` (`dstack_default`, lines 1419-1422). No `internal: true`, no egress allowlist — **every engine can open arbitrary outbound connections [MEDIUM]**; sanctioned engine egress by design: HF fetches (`HF_HUB_OFFLINE=0` always) and the two multimodal media paths (Gemma allowlisted, Qwen3-VL unrestricted — Check 2).

Port `80:80` is published (463) but no server block listens on 80 — the stock default.conf is overwritten by this config target — dead port **[INFO]**.

## Verdict

**Qualified PASS at this layer.** The file hands no logging switch to any engine or proxy, forces OHTTP on for all nine models, keeps every telemetry destination literal, and buffers no plaintext to disk at any hop. The qualifications, in descending order of what they cost the end-to-end claim: **(1)** three in-enclave builds resolve code from PyPI / a mutable tag at deploy time — for whisper the pinned engine digest can be silently replaced by `vllm[audio]` — so for those services the action-log hash pins the *recipe*, not the *code* (no trace on drift); **(2)** FLUX's unpinned `--trust-remote-code` admits HF-head code execution with no trace in near.ai's chain; **(3)** Qwen3-VL's unrestricted media fetch is an active request-driven egress channel its same-file sibling shows how to close; **(4)** C3 — everything any of these nine services prints leaves the TEE twice, unredacted, so the whole posture is conditional on per-image print discipline. Recommend, in-file: pin FLUX's `--revision`; mirror Gemma's two media settings onto Qwen3-VL; pin the three builds (digest base + `pip install --require-hashes` or vendored wheels).

**Unverifiable at this layer (hand-offs):** whether the deployed built images match a rebuild of these Dockerfiles today (build-day PyPI state is unrecorded); whether `/compose/up` env splices surface in the signed action log; runtime warm-cache state shielding FLUX from HF-head drift (state, not config); uvicorn/transformers framework logging inside privacy-filter; `vllm-proxy-rs` internals (deferred to its [source page](/images/docker.io/nearaidev/vllm-proxy-rs/sha256-b183677a5d32267539b9b21ec45327a4f3be0a013afeb608c68c4d76e9472e36.md)); engine print discipline at the configured levels (per-image source pages — load-bearing under C3); the `lmsysorg/sglang@8ece90ad` FLUX base image (observed, not audited — no published page).
