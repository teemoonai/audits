## Check 3 — Gemma-4 media fetch is fully constrained; check every media-capable service **[requested lead — confirmed]**

Gemma-4 is the only multimodal (image) engine on this node, and both its request-driven media controls are set:

- `--allowed-media-domains ${VLLM_ALLOWED_MEDIA_DOMAINS:-prod-files-secure.s3.us-west-2.amazonaws.com}` (`:237`) — a single literal S3 domain as the default allowlist.
- `VLLM_MEDIA_URL_ALLOW_REDIRECTS=0` (`:246`) — redirects off, so the allowlist cannot be bypassed by a 302 to an off-allowlist host.

Both apply to **both** Gemma replicas (they share the `x-gemma-4-31b-common` anchor, `:202-249`, inherited at `:551` and `:581`). Confirmed against the concern that an allowlist without redirect-suppression is a no-op (the failure mode the small-models Qwen3-VL page flagged): here redirects are off, so the allowlist is effective.

**Every other plaintext service that could fetch media, checked:** the three SGLang engines (DeepSeek, both Qwen3.6) are text checkpoints with no multimodal flags and no media-URL handling in their commands (grep-verified — no `media`/`redirect` token on any SGLang command). So on this node there is exactly one media-fetching engine and it is the constrained one — no unconstrained multimodal sibling exists here (unlike small-models, where Qwen3-VL was the unconstrained twin). Residual **[MEDIUM]**: `VLLM_ALLOWED_MEDIA_DOMAINS` is interpolated and not in `allowed_envs`, so the allowlist can be *widened* via the `/compose/up` splice with no measurement change; `VLLM_MEDIA_URL_ALLOW_REDIRECTS=0` is a hard literal and cannot.

## Verdict

**Qualified PASS at this layer.** The file hands no logging switch to any engine or proxy, forces OHTTP on for all four models, fully constrains Gemma-4's media fetch (allowlist + redirects-off, both replicas), keeps every telemetry destination literal, and buffers no plaintext to disk at any hop. The qualifications, in descending order of cost to the end-to-end claim: **(1)** both Qwen3.6 engines run `--trust-remote-code` with no `--revision` — HF-head code execution inside the enclave with no attestation-visible trace; **(2)** the engines' unauthenticated `/configure_logging` (CRITICAL on the engine pages) is reachable from the flat network this file joins and through the allowlist-free `location /` proxies/nginx; **(3)** harness-C3 — everything any of these four families' services prints leaves the TEE twice, unredacted, including to Datadog, so the posture is conditional on per-image print discipline (and on no 30-minute hang given the watchdog-dump HIGH); **(4)** the `/compose/up` splice — documented in this file's own comments — can set `DSV4_RETURN_HIDDEN_STATES` and widen `VLLM_ALLOWED_MEDIA_DOMAINS` with no measurement change. Recommend, in-file: pin `--revision` on both Qwen3.6 engines; front the engines with a path allowlist; the media constraint is the model here — replicate it wherever a multimodal engine is added.
