### Check 3 — Telemetry pipeline: the full stdout chain, and whether anything scrubs **[the priority check]**

**Result at this measurement: engine stdout forks off-box to TWO measured destinations — near.ai's gateway (management records only, from this layer) and, via the measured Datadog agent, `us3.datadoghq.com` (ALL containers). No stage in either chain scrubs.**

The chain, end to end:

1. **Every container writes stdout/stderr to the Docker `json-file` driver** (the four management containers at 100m x 10, `:85-90` etc.; the agent and collector keep themselves on the `local` driver at 20m x 3, `:33-37`, `:63-67`, to avoid tailing their own logs). The inner recipe's engines and proxies use the same `json-file` pattern — their logs land in the same `/var/lib/docker/containers` tree.
2. **The measured `datadog-agent` collects ALL of it:** `DD_LOGS_ENABLED=true` (`:10`), `DD_LOGS_CONFIG_CONTAINER_COLLECT_ALL=true` (`:12`), with the **only** exclusion being itself — `DD_CONTAINER_EXCLUDE_LOGS=name:datadog-agent` (`:13`). Destination: literal `DD_SITE=us3.datadoghq.com` (`:8`). It additionally ingests container journald logs via the measured `journald_config_file` (`:29-31`, `:246-251`) — whose own comment reads `TODO: Add filters to reduce log volume` — and ships process cmdlines (`DD_PROCESS_AGENT_ENABLED=true`, `:14`).
3. **`otelcol-management` tails the same JSON logs** (`include: [/var/lib/docker/containers/*/*-json.log]`, `:260`) and **drops everything that is not management**: `filter/management_logs` (`:334-338`) admits only `compose-manager`, `compose-manager-launcher`, `dns-cloudflare`. A record whose `service.name` failed to resolve satisfies all three inequalities and is **dropped** — fail-closed, the right direction.
4. **Export:** `otlphttp/gateway` -> literal `https://telemetry.infra.near.ai` (`:354`), `Authorization: Bearer ${MONITORING_INGEST_TOKEN}`, disk-backed queue at `/var/lib/otelcol-management/storage` (`:357-364`). Pipelines (`:368-376`): `logs/cvm` and `metrics/self` only — no hostmetrics/docker_stats scrapers on this node.

Findings:

- **[HIGH — systemic, C3] Whatever any plaintext service prints leaves this CVM verbatim, twice.** Via the measured agent to Datadog (this document), and via the inner recipe's `otelcol-contrib` (inverse filter, keeps app containers) to `telemetry.infra.near.ai` (that recipe's `file_sha256` leg — see the [recipe page](/manifests/nearai/cvm-compose-files/prod/qwen35-dsv4-flash/sha256-5be223d330932d118eb8ceee6414304af43c98d9a0f43b8195c8d86dfb77d000.md), Check 4). Neither chain contains any redaction, hashing, or truncation processor. The privacy property degenerates to *"no service prints content"* — which is exactly what the engine pages' CRITICAL (`/configure_logging` flips prompt logging onto stdout at runtime) and HIGH (watchdog token-ID dump on a 30-minute hang, undisableable) put at risk. On this node, if either fires, the content reaches a **third-party US SaaS**, not only near.ai.
- **[MEDIUM] Two measured network ingestion surfaces feed the Datadog pipe:** `DD_OTLP_CONFIG_RECEIVER_PROTOCOLS_GRPC_ENDPOINT=0.0.0.0:4317` with `DD_OTLP_CONFIG_LOGS_ENABLED=true` (`:20`, `:11`), and `DD_DOGSTATSD_NON_LOCAL_TRAFFIC=true` (`:15`). (The inner recipe runs a second open OTLP receiver, `otelcol-contrib:4317/4318` -> near.ai; that one is assessed on the recipe page.)
- **[MEDIUM] Engine stdout isolation at this layer is one OTTL condition wide** (`:334-338`) — measured, so changing it changes `compose_hash`, but the receiver is deliberately CVM-wide. "OFF at this configuration", not "cannot happen".
- **[INFO] `public_logs: false`** — the dstack host-facing log endpoint is off; the host operator cannot read container logs through dstack itself.

This harness sits on the **Datadog-present** side of the fleet's measured-telemetry axis, with three consequences relative to the Datadog-free gpu04 harness ([`9385918d…`](/manifests/measured/sha256-9385918de0a73b861ae833d99fb5be6f7e1c8a50487a835df4f277497c206825.md)):

2. **[MEDIUM] Measured open ingestion surfaces: two** (agent OTLP-logs gRPC on `0.0.0.0:4317`, non-local dogstatsd) versus gpu04's none.
3. **[INFO] Narrower collector:** this node's `otelcol-management` reads only `/var/lib/docker/containers` — no `/hostfs` guest-root mount, no docker socket, no hostmetrics — a smaller measured read surface than gpu04's.

And relative to gpu26 ([`db6943f3…`](/manifests/measured/sha256-db6943f37a4f54bd12144ecbf9f8c780ca14c0c44600a5a9ca09a041d92ba5ca.md)), which shares the Datadog-present posture and the 22-entry env list: same skeleton, but gpu26's `pre_launch_script` adds `swappiness=0` (Check 6) — and the two nodes jointly serve `dsv4-flash`, so this asymmetry is a per-request lottery for that model's users.

## Cross-check synthesis — architectural findings

- **[C1 / HIGH] The measurement does not cover the plaintext stack's configuration.** This hash measures the management harness only; every engine flag, proxy env, nginx rule and app-telemetry filter lives in the runtime-fetched inner recipe, pinned by the signed compose-manager action log. With `MIN_TAG_AGE_HOURS` defaulting to 0, an operator with repo push access plus `BEARER_TOKEN` can deploy a recipe carrying `--log-requests-level 2` for both models with no measurement change. Compensating control: the action-log entry is signed and client-verifiable — transparency plus client verification, not measurement.
- **[C2 / HIGH] The enforcement point is root-equivalent and self-updating.** compose-manager can nsenter/ptrace any process in the CVM, and the launcher swaps its image to any build cosign-signed by a `nearai/compose-manager` CI workflow on the operator-chosen `LAUNCHER_CHANNEL`; the measured digest at `:125` is a `${…:-default}` and the swap survives reboot via `work/.env.launcher`. The anchor is nearai's GitHub org and CI.
- **[C3 / HIGH] Off-box stdout shipping is a fixed feature, and on this node it is the fleet's widest published shape:** all-container collection to Datadog (measured) plus app-container collection to near.ai (recipe leg), with no scrubbing at any hop of either pipeline.
- **[C4 / HIGH — topology] This document creates the shared, unrestricted `dstack_default` network on which the engines' unauthenticated `/configure_logging` sits.** Containment is available at this layer and is not taken.
