# Deployment Manifests & Configuration — Privacy Audit

> Method: [`/notes/method.md`](/notes/method.md) (§4 Manifest-only checks) · Architecture: [`/notes/ARCHITECTURE.md`](/notes/ARCHITECTURE.md)

**Role:** the layer that makes the plaintext-handling processes trustworthy. An operator can change only the env vars in `allowed_envs` without a new hardware measurement — so the questions are what the fixed config does, and what the allowed envs could do.

**Why this node matters.** The engine it fronts, [`sglang@1c64fde9`](/images/docker.io/lmsysorg/sglang/sha256-1c64fde976bdf0d56474a30bccbcfc19667e5b3ab34c826a534c9d6aaca41212.md), carries the repo's standing **CRITICAL** (unauthenticated `/configure_logging` — full prompt+output logging and arbitrary-path request dumping at runtime, no restart, no attestation-visible change) and **HIGH** (an undisableable hang-time dump of prompt and output token ids), and that page notes its blast radius is *the largest in the fleet* — 1M context, `--max-running-requests 256`, and a domain whose long-context traffic has exactly one backend. **How exposed those are is decided by this document and by the recipe**: who can reach port 8000, and where stdout goes. On this node the answer to the second question is worse than on its sibling, because a Datadog agent is measured in.

### Check 2 — Privileges and mounts

- **[HIGH — architectural] `compose-manager` is root-equivalent and can read engine memory.** `pid: host` (`:147`), `cap_add: [SYS_ADMIN, SYS_PTRACE]` (`:148-150`), read-write `/var/run/docker.sock` (`:152`), `/var/run/dstack.sock` (`:153`), decrypted CVM env at `/dstack/.host-shared/.decrypted-env:/app/.env:ro` (`:154`), shared `work` volume (`:155`). The in-manifest comment (`:130-146`) states the rationale: `nsenter -t 1 -m -u -i -n -p` into PID 1's namespaces. With host PID namespace + `SYS_PTRACE` it can attach to any process in the CVM — **including the sglang process holding 1M-token prompt plaintext**. Capability, not configured behavior: the [`5165400d` source review](/images/docker.io/nearaidev/compose-manager/sha256-5165400d9eb43ab5da36986a85de0ba55f3fb4d05211c4397ecc4bde3ef0113b.md) traced the binary and found no code path that uses it.
- **[HIGH — architectural] `compose-manager-launcher` runs `network_mode: host` (`:186`) with read-write `docker.sock` (`:188`)** and the decrypted env read-only (`:192`) — and **this build has no resolvable source** (Check 5). A root-capable component inside the measured TCB whose bytes cannot be tied to any public tree.
- **[MEDIUM] `datadog-agent` mounts the container log store and the host process tree**: `/var/run/docker.sock:ro` (`:22`), `/proc/:/host/proc/:ro` (`:23`), `/sys/fs/cgroup:ro` (`:24`), **`/var/lib/docker/containers:ro` (`:25`)**, `/run/log/journal:ro` (`:26`), `/run/systemd/:ro` (`:27`). That is read access to **every container's stdout/stderr on the box**, plus (with `DD_PROCESS_AGENT_ENABLED=true`, `:14`) process command lines. See Check 3 for where it goes.
- **[INFO] `otelcol-management` is narrower here than on the sibling node**: it mounts only `/var/lib/docker/containers:ro` (`:53`) and its own storage volume (`:54`) — **no `docker.sock`, no `/:/hostfs:ro`**, and no `hostmetrics`/`docker_stats` receivers. The collector on this node cannot read the guest root filesystem.
- **[INFO] `certbot` / `certbot-init`** hold the `*.completions.near.ai` private key in the `certs` volume; TLS terminates in-enclave, key never leaves the CVM. PASS for the privacy model.
- **No `privileged: true` in this document.** The privileged, `ipc: host`, root proxy lives in the inner recipe.

### Check 3 — Telemetry pipeline: the full stdout chain, and whether anything scrubs **[priority]**

**Result: [HIGH — systemic]. Every container's stdout leaves this CVM by measured configuration, to two independent backends, with no scrubbing at any hop.**

**Path A — Datadog (third-party, United States).** This is the path that does **not** exist on the sibling node.

- `datadog-agent` (`:3`), image `datadog/agent@sha256:5556fb80…` (`:4`, digest-pinned, [audited](/images/docker.io/datadog/agent/sha256-5556fb80b952832719a76b016f905616c76ee0989a239c4680c6220148e865d6.md)).
- `DD_LOGS_ENABLED=true` (`:10`) and **`DD_LOGS_CONFIG_CONTAINER_COLLECT_ALL=true`** (`:12`) — collect **all** container logs, with only `DD_CONTAINER_EXCLUDE_LOGS=name:datadog-agent` (`:13`) excluded (itself, to avoid a feedback loop). **Nothing else is excluded — not the engine, not the proxy, not nginx.**
- Source: the `/var/lib/docker/containers:ro` mount (`:25`); plus a journald collector with `container_mode: true` (`:242-248`) whose config carries an in-manifest **`# TODO: Add filters to reduce log volume`** (`:247`) — an acknowledged unfiltered firehose.
- `DD_PROCESS_AGENT_ENABLED=true` (`:14`) additionally ships process command lines.
- Destination: `DD_SITE=us3.datadoghq.com` (`:8`) — **literal**, `DD_ENV=prod` (`:9`), authenticated by `DD_API_KEY` (`:7`, operator-selected account).
- **[MEDIUM] An open OTLP ingestion surface on the agent**: `DD_OTLP_CONFIG_RECEIVER_PROTOCOLS_GRPC_ENDPOINT=0.0.0.0:4317` (`:20`) with **`DD_OTLP_CONFIG_LOGS_ENABLED=true`** (`:11`). Any container on the shared network (Check 4) can push OTLP **logs** — not merely traces — straight into the Datadog pipeline. No scrubbing processor exists on that path. (`DD_DOGSTATSD_NON_LOCAL_TRAFFIC=true`, `:15`, likewise accepts metrics from any container.)

**Path B — near.ai's telemetry gateway.** Identical to the sibling node's.

- `otelcol-management` (`:40`), image `otel/opentelemetry-collector-contrib@sha256:85ac41c2…` (`:41`, digest-pinned, [audited](/images/docker.io/otel/opentelemetry-collector-contrib/sha256-85ac41c2db88d0df9bd6145e608a3cb023f5d8443868adbfbbf66efb51087917.md)), `user: "0:0"`.
- Its `filelog/docker_containers` receiver (`:255`) tails `/var/lib/docker/containers/*/*-json.log` — again **all** containers, engines included.
- `transform/docker_metadata` (`:320`) resolves `service.name`; **`filter/management_logs` (`:330`) drops everything that is not `compose-manager`, `compose-manager-launcher` or `dns-cloudflare`.** A record whose `service.name` is nil satisfies all three inequalities and is dropped — **fail-closed**, the right direction.
- Export: `otlphttp/gateway` -> `endpoint: https://telemetry.infra.near.ai` (`:350`), literal, bearer `${MONITORING_INGEST_TOKEN}`, disk-backed sending queue. Pipelines `logs/cvm` (`:365-368`) and `metrics/self` (`:369-372`).
- Plus **Path B'**: the inner recipe's own `otelcol-contrib` runs the *inverse* filter — it keeps the app containers (both engines' class of service, the proxy, nginx, dcgm, registrar) and exports to the same near.ai gateway. Assessed on the [TP8 recipe page](/manifests/nearai/cvm-compose-files/prod/GLM-5.2-W4AFP8-SGL-TP8/sha256-db6f4e8ffd0324fcc3b2c3ef51ec2a4735b888bd9293057295d9161c9585bf38.md), Check 3.

**Findings:**

- **[HIGH] The measured configuration guarantees that anything a plaintext-handling service prints leaves the TEE — twice, to two different backends, one of them a third-party US SaaS.** No receiver ingests request bodies *by configuration*, and every destination is literal. But the manifest does not *contain* content capture; it *ensures export* if capture ever happens. Combined with the engine's CRITICAL (`/configure_logging`, one unauthenticated POST away) this is the sharpest edge on this node: **the switch is in the engine, the pipe is here, and the pipe is measured on.**
- **[HIGH] No scrubbing exists at any hop of either path.** The OTel processor chain is `memory_limiter, resource, transform/docker_metadata, filter/management_logs, groupbyattrs/docker_service, batch` (`:367`) — none redacts. The Datadog agent's log pipeline has no processor stanza at all. The `com.datadoghq.ad.logs` labels the inner recipe attaches are *routing metadata*; they tag streams, they never select or scrub content.
- **[MEDIUM] The Datadog path has no equivalent of the OTel filter.** Where the near.ai path drops non-management records by an explicit, measured OTTL condition, Datadog's `CONTAINER_COLLECT_ALL` has only a name-based *exclude* list containing one entry. The isolation properties of the two paths are not comparable: one is allow-listed, the other is collect-everything.
- **[INFO] `public_logs: false`** — the dstack host-facing log endpoint is off, removing one obvious sink for the host operator.
- **[INFO] Metrics paths are counters only** (`prometheus/self`, `:288`).

## Cross-check synthesis — architectural findings

- **[C1 / HIGH] The measurement does not cover the plaintext stack's configuration.** This hash measures the harness; every engine flag, proxy env, nginx rule and app-telemetry filter lives in the runtime-fetched recipe, pinned by the signed action log (`file`/`commit`/`file_sha256`), not by hardware. An operator with repo push access plus `BEARER_TOKEN` could deploy a recipe carrying `--log-requests --log-requests-level 3` — for the flagship and its long-context tier at once — with no measurement change. Compensating control: the action-log entry is signed and client-verifiable, so clients that pin and check the inner-compose hash detect it. **Transparency plus client verification, not measurement.** The `MIN_TAG_AGE_HOURS=2` literal adds a two-hour floor, which is a real (if modest) improvement over the sibling's operator-settable 0.
- **[C2 / HIGH] The enforcement point is root-equivalent, self-updating, and here partly unauditable.** compose-manager can `nsenter`/ptrace any process in the CVM; the launcher swaps its image to any cosign-signed `nearai/compose-manager` CI build on the operator-chosen channel; the measured digest is a `${…:-default}` and the swap survives reboot via `work/.env.launcher`. On this node the launcher performing those swaps has **no resolvable source**, so the "bounded by cosign identity" argument rests on a binary nobody outside near.ai can read.
- **[C3 / HIGH] Global stdout exfiltration is a fixed, measured feature — to two backends.** Datadog (all containers, collect-all, literal US endpoint) plus near.ai (management here, app containers via the recipe's collector). The manifest proves no content is collected **only if no service prints content**.
- **[C4 / HIGH — topology] This document creates the shared, unrestricted `dstack_default` network on which the engine's unauthenticated `/configure_logging` sits**, and adds to it an OTLP-logs listener on `0.0.0.0:4317` that any co-resident container can write to. Containment is available at this layer and is not taken.

## Verdict

**Qualified PASS.**

- **Within hardware-measured config + `allowed_envs`:** upheld. None of the 21 allowed envs is a debug, log-level, log-bodies or telemetry-content switch; every telemetry destination and log level is a literal; the near.ai filter is fail-closed. An operator cannot flip on content capture through the measured env channel alone.
- **As an end-to-end claim:** the invariant this layer delivers is the fleet's — **"content capture cannot be enabled without either changing the measurement or leaving a signed, client-verifiable trace"** — via C1 and C2, with C3 making the guarantee wholly conditional on every plaintext service's print discipline, and C4 leaving the engine's unauthenticated admin surface reachable from a shared network this document defines.
- **Weaker than its sibling in two respects that matter**, both invisible to the client except through the `compose_hash`: a measured Datadog agent shipping every container's stdout to a third-party US SaaS, and a root-capable launcher build with no resolvable source. **Stronger in one:** a literal two-hour tag soak instead of an operator-settable zero.
