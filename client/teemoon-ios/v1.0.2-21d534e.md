### Findings

### MEDIUM (deployed: yes — since 1.0) — the near.ai API key is written in cleartext to the shared URL cache on disk by the attestation-report fetch

Every authenticated fetch outside the chat request goes through `URLSessionHTTP`,
whose default is `URLSession.shared` (`Inference/HTTPClient.swift:19`), and no
code anywhere configures `URLCache` or a cache policy. The model
attestation-report request sets `Authorization: Bearer <near.ai key>`
(`Confidential/AttestationService+Model.swift:109`; `:104` at 1.0) and near.ai
serves that report without `Cache-Control: no-store`, so CFNetwork archives the
whole request — header value included — into
`Library/Caches/ai.teemoon.app/Cache.db`. After one live session the database
held nine `glm-5-2.completions.near.ai/v1/attestation/report` entries whose
archived `Authorization` header equals the key on the developer's host file
(compared, never printed). The same session default sits behind the gateway
report, the key checks, the signature fetch, the catalogs, the endpoint
probes, the adapters and the Brave search (`X-Subscription-Token`); which of
those also land on disk depends only on each server's cache headers.

**Leak scenario.** The key exists on disk outside the Keychain, under the
container's default protection (readable after the first unlock) and outside
the Keychain's access control, and it survives the user deleting the key from
the app until the cache evicts it. Anyone with file access to the container —
a forensic extraction of a once-unlocked device, a jailbroken device, a
backup tool that ignores the Caches exclusion — reads it. `Library/Caches` is
excluded from iCloud and Finder backups by the system, which bounds this to
device access. It is a key at rest, not a network exfiltration, so it is
MEDIUM rather than HIGH; but the page's "Keychain and nowhere else on disk"
claim is false at every shipped release, and neither source read caught it.

**Remediation (client repo).** Give every authenticated request a session
whose configuration has `urlCache = nil` (or `.ephemeral`), or set
`cachePolicy = .reloadIgnoringLocalCacheData` per request; call
`URLCache.shared.removeAllCachedResponses()` when a key is removed or
changed, and once on first launch of the fixed build to purge existing
copies. A regression test that fetches through the production `HTTPClient`
with a marker header and asserts the marker is absent from
`URLCache.shared` would pin it.

### LOW (deployed: yes — since 1.0) — the user-edited system prompt is stored in UserDefaults, outside the protected store and inside backups

`AppSettings.systemPrompt` reads and writes `UserDefaults`
(`Settings/AppSettings.swift:28`, `:32`), edited in Settings → Chats through
a `TextEditor` (`Views/Settings/ChatsSettingsView.swift:24`), and lands in
`Library/Preferences/ai.teemoon.app.plist` — observed in the container after
the sessions. That text is sent as the system message of every request, so
it is prompt plaintext the user wrote, and it can carry exactly what the
store's hardening exists to protect (who they are, what they are working on).
Preferences carry the container's default protection class and are included
in iCloud and encrypted Finder backups. Most users never change the default
prompt, which is why this is LOW. **Remediation:** keep it in the hardened
store, or write it to a file with the store's protection class and backup
exclusion.

### Residuals — by design, stated not hidden

Carried from the 1.0 page: opt-in web search is content-driven egress to one
fixed host; provider keys restore via encrypted backup; an unattested provider
is plaintext by definition; user-initiated copies go to the general pasteboard;
E2EE metadata is plaintext by protocol. New at this release:

- **A no-tap re-send exists.** An on-device turn cut off by backgrounding is
  re-sent once on return (`Views/Chat/ChatView.swift:676`), through the same
  gate as a tap, to the provider already chosen, carrying only the user's own
  last message. Not a new destination; recorded because it needs no user
  action.
- **A developer-only stderr capture ships in the release binary.**
  `captureNativeLogIfAsked` (`App/teemoonApp.swift:30-39`) redirects stderr —
  where the LiteRT runtime logs — to `Documents/native.log` when
  `TEEMOON_NATIVE_LOG=1` is in the launch environment. It is env-gated, not
  `#if DEBUG`-fenced, so the code is present in the App Store build; an App
  Store launch has no environment, `Documents` is not exposed via file sharing,
  and reaching it needs Xcode or `devicectl` on a Developer-Mode device the
  user already controls. The app's own stderr lines carry no message text; what
  the native binary prints is the standing *not traced* item above. Hygiene,
  not a leak; a `DEBUG` fence would remove the question.

### Controls that would change the verdict

- A renderer capability that fetches on render (previews, embeds, a web view).
- A second derivation of send authorization anywhere a message can start.
- A model-callable tool that fetches a model-chosen URL or reads other threads.
- `captureNativeLogIfAsked` becoming a user-facing setting.
- A dependency added to `Package.resolved` with its own network client.
- Any new authenticated fetch through `URLSession.shared` while the URL cache
  is still enabled — it will land on disk if the server allows caching.

### Verdict: QUALIFIED-PASS

Messages: private at `21d534e`. The delta adds one network sink (model
downloads) that carries nothing from the conversation, one no-tap send that
goes through the existing gate, and diagnostics that carry no content; a live
session opened no endpoint the map does not name; every property the 1.0
verdict rests on holds and the renderer defence is stronger. Keys: they leave
the device only to their own provider, but the runtime pass found the near.ai
key at rest in the shared URL cache on disk (MEDIUM, since 1.0), so "Keychain
and nowhere else" does not hold until the client stops caching authenticated
requests. One LOW: the user-edited system prompt is in UserDefaults and
backed up. The on-device runtime's egress remains unobserved.
