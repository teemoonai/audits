### Traced — from each place plaintext exists, to every sink the delta touches

**Prompt and reply text.**

- *Re-send after backgrounding.* iOS revokes GPU access from a backgrounded
  app, so an on-device turn in flight is abandoned
  (`Inference/LiteRTTransport.swift`, polling `applicationState == .background`)
  and the user's last message is re-asked once when the app returns —
  `Views/Chat/ChatView.swift:676` → `retry(from:)` → `prepareSend(trust:
  confidentialSession.sendPolicy)` (`:851-862`), then the missing-key and
  unsealed-send refusals in `Chat/ChatViewModel.swift:225-238`. Same gate as a
  tap, same provider the user chose, same message. A no-tap send, not a new
  destination. **Clean; recorded as a residual because it is no-tap.**
- *New log lines on the inference path.* `DiagLog` (`Inference/LocalRuntime.swift:239-246`)
  writes to stderr only when `TEEMOON_NATIVE_LOG=1` is in the launch

  carries message text — the one reference to an answer is its character
  count. New `logger.error/warning` lines in `ChatGeneration.swift`,
  `LiteRTTransport.swift` and `ChatViewModel.swift` interpolate fixed
  literals, counts, or the provider name at `.public`; no body, no delta text.
  **Clean.**
- *Renderer.* The `imageURL` strip is unconditional in the one shared parser
  (`Views/Chat/MarkdownParseCache.swift:52`, `:68`) and the non-fetching loader

  `App/RequestLLMIntent.swift:78-84`; the new `hasCredential` guard at `:87-90`

- *Store and sidecars.* Untouched by the delta; re-read: `hardenConversationStore`
  at `App/teemoonApp.swift:261-275` (called `:202`) applies
  `.completeUnlessOpen` + backup exclusion to the store, `-wal` and `-shm`;
  `Chat/Search/ChatSearchService.swift:55` (`configure`) and `:85`

### Residuals — by design, stated not hidden

Carried from the 1.0 page: opt-in web search is content-driven egress to one
fixed host; provider keys restore via encrypted backup; an unattested provider
is plaintext by definition; user-initiated copies go to the general pasteboard;
E2EE metadata is plaintext by protocol. New at this release:

- **A no-tap re-send exists.** An on-device turn cut off by backgrounding is
  re-sent once on return (`Views/Chat/ChatView.swift:676`), through the same
  gate as a tap, to the provider already chosen, carrying only the user's own
  last message. Not a new destination; recorded because it needs no user
  action.
- **A developer-only stderr capture ships in the release binary.**
  `captureNativeLogIfAsked` (`App/teemoonApp.swift:30-39`) redirects stderr —
  where the LiteRT runtime logs — to `Documents/native.log` when
  `TEEMOON_NATIVE_LOG=1` is in the launch environment. It is env-gated, not
  `#if DEBUG`-fenced, so the code is present in the App Store build; an App
  Store launch has no environment, `Documents` is not exposed via file sharing,
  and reaching it needs Xcode or `devicectl` on a Developer-Mode device the
  user already controls. The app's own stderr lines carry no message text; what
  the native binary prints is the standing *not traced* item above. Hygiene,
  not a leak; a `DEBUG` fence would remove the question.

### Controls that would change the verdict

- A renderer capability that fetches on render (previews, embeds, a web view).
- A second derivation of send authorization anywhere a message can start.
- A model-callable tool that fetches a model-chosen URL or reads other threads.
- `captureNativeLogIfAsked` becoming a user-facing setting.
- A dependency added to `Package.resolved` with its own network client.

### Verdict: QUALIFIED-PASS

Private at `21d534e`. The delta adds one network sink (model downloads) that
carries nothing from the conversation, one no-tap send that goes through the
existing gate, and diagnostics that carry no content. Every property the 1.0
verdict rests on holds; the renderer defence is stronger. The on-device
runtime binary remains unread.
