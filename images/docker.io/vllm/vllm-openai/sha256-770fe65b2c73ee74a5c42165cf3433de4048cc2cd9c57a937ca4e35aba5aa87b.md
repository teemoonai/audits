# vLLM inference engine (DeepSeek-V4-Flash, DP4 x TP1 + EP) — Privacy Audit

> Part of the near.ai inference-path privacy audit. Method: [/notes/method.md](/notes/method.md).

- **Image:** `vllm/vllm-openai@sha256:770fe65b2c73...` (= `ffd46bfa`, v0.26.0 line)
- **Source:** https://github.com/vllm-project/vllm/tree/ffd46bfab2128bb84146050e98b51a617c6575ab
- **Location:** near.ai model-node CVM, `prod/dsv4-qwen36-gemma4.yaml`, one container on GPUs 0-3 behind `proxy-dsv4-flash` (`vllm-proxy-rs`, `VLLM_DATA_PARALLEL_SIZE=4`). Container stdout is `json-file` logged with the `com.datadoghq.ad.logs` label baked into each line (`x-logging-conf`), and the recipe's own `otelcol-contrib` service tails `/var/lib/docker/containers/*/*-json.log`, keeps every line whose label carries a `model:` tag (`filter/app_logs`), and exports it to `https://telemetry.infra.near.ai` (`exporters.otlphttp/gateway`) with **no redaction stage**. `:8000/metrics` is scraped by the same collector (`prometheus/apps`, job `vllm-model-vllm-dsv4-flash-fp4-dp4`) and by a Datadog openmetrics check (`com.datadoghq.ad.instances`). So anything this engine prints at INFO or above is egress, not a local log.
- **Role:** the inference engine — one of the two parties allowed to see plaintext. Replaces the sglang engine that served this model on the previous recipe revision.
- **Verdict:** no plaintext reaches any log, disk, or non-model network destination at the deployed flags in normal operation; the engine-crash dump that leaked token IDs at v0.12.0 is redacted here; the flight-recorder dump the deployment arms via `TORCH_NCCL_DUMP_ON_TIMEOUT` writes collective metadata and stack frames, not tensor content, to a container-local file; usage-stats phone-home to `stats.vllm.ai` is ON (metadata only)

### Controls that would change the verdict

| Control | Effect |
|---|---|
| Set `VLLM_NO_USAGE_STATS=1` (or `VLLM_DO_NOT_TRACK=1`) in the service env | Removes the only steady-state non-model egress (`stats.vllm.ai`) and the local `usage_stats.json`; cheap, no downside |

### Verdict: no exfiltration path for chat plaintext at the deployed flags in normal operation

Request/response logging is opt-in and off, with the deprecated alias removed outright; the response-body middleware, dev routes, profiler, tracing and runtime-LoRA are all gated at process start by values the attested compose leaves unset; there is no runtime logging switch; disk artifacts are config-hash-keyed; the KV cache has no CPU or disk tier; metrics and access logs are aggregate/metadata only; DP internals bind Unix sockets and loopback. The crash-path token-ID leak found at v0.12.0 is closed at this commit by `CachedRequestData.anon_repr`, leaving sampling params (client `stop` strings) as the residue. The flight-recorder dump the deployment arms records tensor shapes and dtypes, never content, to a container-local file. Two real notes: (1) default-on usage telemetry to `stats.vllm.ai` (deployment metadata, no content) — the only steady-state non-model egress; (2) a new latent path this version introduces — the shared parser engine logs 80-character fragments of model-generated tool-call arguments at DEBUG, outside any flag, so the log level is now load-bearing on its own.

**Residuals.** Image↔source correspondence rests on a builder-asserted OCI label, not a signed provenance attestation — everything above assumes the image binaries match tree `ffd46bfa`. Native components (torch beyond the files read, NCCL, CUDA, FlashInfer, DeepGEMM, the DeepSeek-V4 CUDA kernels) and the co-resident proxy, nginx, dcgm, sglang and otelcol containers were not audited here; the proxy sees plaintext by design. Whether enclave egress policy blocks `stats.vllm.ai`, what `telemetry.infra.near.ai` retains from this container's stdout, whether a Datadog agent in the outer harness also tails it, and what the `ipc: host` neighbours actually do with the shared IPC namespace could not be established from this source. Absence of evidence in the untraced components is not proof.
