# SGLang inference engine (Qwen3.6) — Privacy Audit

**Image:** `docker.io/lmsysorg/sglang:v0.5.12-cu129@sha256:9e02c8e1fe27…`, run directly (not rebuilt in-enclave; the `dsv4-qwen36-gemma4.yaml` compose pulls the public tag).
**Source:** [`github.com/sgl-project/sglang`](https://github.com/sgl-project/sglang/tree/127b9e3283f7c2a43234b852ff5c9f1796d53624) @ `127b9e32` (release `v0.5.12`).
**Location:** Model node CVM — the deepest point of the path.
**Role:** **the model.** It *must* see plaintext to run inference. The question is whether, at the deployed launch flags, it logs / persists / egresses that content.
**Verdict:** **PRIVATE at the deployed flags** — with one CRITICAL residual: an unauthenticated runtime logging switch guarded only by external network segmentation.

### CRITICAL — `/configure_logging` is an unauthenticated runtime switch that enables full prompt+output logging and disk dumps

`POST /configure_logging` is registered at `AuthLevel.ADMIN_OPTIONAL` ([`http_server.py:1395-1399`](https://github.com/sgl-project/sglang/blob/127b9e3283f7c2a43234b852ff5c9f1796d53624/python/sglang/srt/entrypoints/http_server.py#L1395-L1399)):
```
@app.api_route("/configure_logging", methods=["GET", "POST"])
@auth_level(AuthLevel.ADMIN_OPTIONAL)
async def configure_logging(obj: ConfigureLoggingReq, request: Request):
    _global_state.tokenizer_manager.configure_logging(obj)
```
At the deployed config (no `--api-key`, no `--admin-api-key`, and **no endpoint uses `AuthLevel.ADMIN_FORCE`** — all are `ADMIN_OPTIONAL`), the auth middleware is **not even installed**: it is added only if `api_key or admin_api_key or app_has_admin_force_endpoints(app)` ([`http_server.py:2191-2201`](https://github.com/sgl-project/sglang/blob/127b9e3283f7c2a43234b852ff5c9f1796d53624/python/sglang/srt/entrypoints/http_server.py#L2191-L2201)) — all three are false here. Even if it were installed, `decide_request_auth` for `ADMIN_OPTIONAL` with no keys returns `AuthDecision(allowed=True)` ([`auth.py:128-138`](https://github.com/sgl-project/sglang/blob/127b9e3283f7c2a43234b852ff5c9f1796d53624/python/sglang/srt/utils/auth.py#L128-L138)). Unlike the "admin" endpoints (e.g. `/clear_hicache_storage_backend`, which self-reject via an explicit `admin_api_key` check), `configure_logging` has **no such guard** and simply runs.

The handler ([`tokenizer_manager.py:1582-1598`](https://github.com/sgl-project/sglang/blob/127b9e3283f7c2a43234b852ff5c9f1796d53624/python/sglang/srt/managers/tokenizer_manager.py#L1582-L1598)) applies a client-supplied `ConfigureLoggingReq` ([`io_struct.py:1762-1769`](https://github.com/sgl-project/sglang/blob/127b9e3283f7c2a43234b852ff5c9f1796d53624/python/sglang/srt/managers/io_struct.py#L1762-L1769)) that can set at runtime, with no restart:
```
log_requests, log_requests_level, log_requests_format,
dump_requests_folder, dump_requests_threshold, crash_dump_folder, dump_requests_exclude_meta_keys
```
Setting `log_requests=true, log_requests_level=3` → `max_length = 1<<30`, no `skip_names` ([`request_logger.py:227-232`](https://github.com/sgl-project/sglang/blob/127b9e3283f7c2a43234b852ff5c9f1796d53624/python/sglang/srt/utils/request_logger.py#L227-L232)) → full untruncated input + output logged. Setting `dump_requests_folder=<path>` → every finished request (prompt object + output) pickled to `.pkl` on disk ([`tokenizer_manager.py:2219-2249`](https://github.com/sgl-project/sglang/blob/127b9e3283f7c2a43234b852ff5c9f1796d53624/python/sglang/srt/managers/tokenizer_manager.py#L2219-L2249)).
- **Deployed status:** OFF (nothing has called it), but **flippable by anyone who can reach sglang's `0.0.0.0:8000` with zero credentials.** sglang has no auth in the measured config; the only barrier is external proxy/network path-filtering, which lives **outside the measured launch config** and was not verifiable from this source.
- **Activates on:** one HTTP POST/GET. This is the single most material residual for the deployment.

### HIGH (deployed: OFF) — `--log-requests` discloses full prompt + response

`RequestLogger.log_received_request` / `log_finished_request` emit the prompt object and output, but both early-return `if not self.log_requests` ([`request_logger.py:94`](https://github.com/sgl-project/sglang/blob/127b9e3283f7c2a43234b852ff5c9f1796d53624/python/sglang/srt/utils/request_logger.py#L94), [`:165`](https://github.com/sgl-project/sglang/blob/127b9e3283f7c2a43234b852ff5c9f1796d53624/python/sglang/srt/utils/request_logger.py#L165)). The raw OpenAI chat payload is additionally logged, but only when `log_requests and log_requests_level >= 2` ([`serving_base.py:89-90`](https://github.com/sgl-project/sglang/blob/127b9e3283f7c2a43234b852ff5c9f1796d53624/python/sglang/srt/entrypoints/openai/serving_base.py#L89-L90)).
Content redaction is level-gated in `_compute_metadata` ([`request_logger.py:200-232`](https://github.com/sgl-project/sglang/blob/127b9e3283f7c2a43234b852ff5c9f1796d53624/python/sglang/srt/utils/request_logger.py#L200-L232)): level 0 skips `{text, input_ids, input_embeds, image_data, audio_data, video_data, lora_path, sampling_params}` and output `{text, output_ids, embedding}`; level 1 same minus `sampling_params`; **level ≥2 logs content** (`max_length=2048` at 2, `1<<30` at 3).
**Deployed status:** the launch passes `--log-requests-level 0` but **not `--log-requests`**, so `log_requests=False` ([`server_args.py:474`](https://github.com/sgl-project/sglang/blob/127b9e3283f7c2a43234b852ff5c9f1796d53624/python/sglang/srt/server_args.py#L474)) and every logger early-returns — the level flag is **inert**. **Activates on:** adding `--log-requests`, or the CRITICAL endpoint. If enabled, output goes stdout → Docker json-file → the node's log pipeline, i.e. off-box.

### Verdict: PRIVATE at deployed flags

On the measured launch command/env, the engine does **not** log, persist, or egress user plaintext: request logging disabled (`--log-requests` absent, `--log-requests-level 0` inert), every disk-dump feature off (dump/crash/tensor folders unset, crash-dump path early-returns, no v0.5.12 py-spy/coredump-before-crash path), prefix/KV cache RAM-only, metrics content-free pull-based counters, no analytics/tracing exporters active. Prompt/response content stays in process memory for the request's lifetime. This holds identically for both the 27B and 35B replicas (same image/digest, same flags but `--model-path`).

**Residuals (why not unconditional):**
1. **Unauthenticated `/configure_logging` (CRITICAL)** — the engine ships an open runtime switch to enable full logging + disk dumps; at the deployed config the auth middleware is not even installed, so the only guard is external proxy/network segmentation, which is outside the attested sglang boundary and unverified here. Should be closed inside the engine boundary (`--admin-api-key`, or attest the proxy path allowlist).
2. **`--trust-remote-code` ON with no `--revision` pin** — third-party model-repo Python runs in-process, at an unpinned checkpoint revision.
3. **Front-door proxy/OHTTP layer + the node log pipeline** were out of scope; they carry sglang stdout, which only matters if #1 or `--log-requests` is ever activated.
4. A `sglang.private.*`-style exporter hook, if the base image bundled one outside this OSS tree, could add request exporters invisibly; not observed, but the image is not build-attested by near.ai (third-party Docker Hub image, label self-attestation only).
