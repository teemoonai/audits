### CRITICAL — `/configure_logging` is an unauthenticated runtime switch to enable full prompt+output logging and disk dumps
[`http_server.py:1402-1406`](https://github.com/sgl-project/sglang/blob/8805f4cf166649d0ab7cd728df514ed476690115/python/sglang/srt/entrypoints/http_server.py#L1402-L1406) exposes `POST /configure_logging` at `AuthLevel.ADMIN_OPTIONAL`. **With no api_key and no admin_api_key configured (the deployed state), `decide_request_auth` returns `allowed=True`** ([`auth.py:137-138`](https://github.com/sgl-project/sglang/blob/8805f4cf166649d0ab7cd728df514ed476690115/python/sglang/srt/utils/auth.py#L137-L138)). The handler ([`tokenizer_manager.py:1633-1649`](https://github.com/sgl-project/sglang/blob/8805f4cf166649d0ab7cd728df514ed476690115/python/sglang/srt/managers/tokenizer_manager.py#L1633-L1649), `ConfigureLoggingReq`) can set at runtime: `log_requests=true`, `log_requests_level=3`, `dump_requests_folder=<path>`, `crash_dump_folder=<path>`. Level 3 → `max_length = 1<<30` ([`request_logger.py:227-228`](https://github.com/sgl-project/sglang/blob/8805f4cf166649d0ab7cd728df514ed476690115/python/sglang/srt/utils/request_logger.py#L227-L228), full input/output, no redaction); a dump folder → every finished request pickled to disk ([`tokenizer_manager.py:2279-2355`](https://github.com/sgl-project/sglang/blob/8805f4cf166649d0ab7cd728df514ed476690115/python/sglang/srt/managers/tokenizer_manager.py#L2279-L2355)).
- **Deployed status:** OFF (nothing has called it), but **flippable by anyone who can reach sglang's `0.0.0.0:8000` with zero credentials.** sglang has no auth in the measured config; the only barrier is the proxy/nginx path-filtering, which lives **outside the measured launch config**. Per [manifests.md](/manifests/nearai/cvm-compose-files/prod/GLM-5.1-SGL-AWQ-TP4/sha256-eb00b404e3218e2e8c8ab8da5845af10ce79929fd232fe8ac3d2f688582817be.md), the compose network is a **flat `dstack_default` bridge with no `internal: true`** — so a co-resident container could reach it directly.
- **Activates on:** one HTTP POST. The mitigating control (path allowlist / auth) is NOT inside sglang's measured boundary. *(The prior run rated this HIGH and emphasized external non-exposure; this run rates it CRITICAL because sglang itself is unauthenticated and the guard is external/unverified.)*

### HIGH (deployed: OFF) — Request logging discloses full prompt+response when `--log-requests` is set
`RequestLogger.log_received_request`/`log_finished_request` ([`request_logger.py:88-191`](https://github.com/sgl-project/sglang/blob/8805f4cf166649d0ab7cd728df514ed476690115/python/sglang/srt/utils/request_logger.py#L88-L191)) emit prompt text, decoded input, and output; at level ≥2 the serving layer also logs the raw OpenAI payload ([`serving_base.py:88-90`](https://github.com/sgl-project/sglang/blob/8805f4cf166649d0ab7cd728df514ed476690115/python/sglang/srt/entrypoints/openai/serving_base.py#L88-L90)). At level 0/1 those fields are in `skip_names` — but the deployed `--log-requests-level 0` is **inert because `--log-requests` is absent** → `log_requests=False`, every logger early-returns (`:94-95,165-166`). **Activates on:** adding `--log-requests` or the CRITICAL endpoint. If enabled, output goes stdout → Docker json-file → otelcol filelog → `telemetry.infra.near.ai`, i.e. **off-box**.

### INFO — Disk-persistence features all OFF at deployed flags
Crash-dump (`--crash-dump-folder` None → early-return [`tokenizer_manager.py:2357-2361`](https://github.com/sgl-project/sglang/blob/8805f4cf166649d0ab7cd728df514ed476690115/python/sglang/srt/managers/tokenizer_manager.py#L2357-L2361)); per-request metrics file (`--export-metrics-to-file` False/None → `write_record` not called); tensor dumps (None); all `SGLANG_*` disk writers (profiler, expert-distribution recorder, cuda-coredump, HiCache storage dirs) default off/empty and **none set** in the deployed env; hierarchical/L3 disk cache off. **Prefix/KV cache is GPU/host RAM only — no disk tier at deployed flags.**

### INFO — No per-request client field triggers server-side dump/persist
`GenerateReqInput.log_metrics` only *gates* dumping when a server-side folder is already set ([`tokenizer_manager.py:1940`](https://github.com/sgl-project/sglang/blob/8805f4cf166649d0ab7cd728df514ed476690115/python/sglang/srt/managers/tokenizer_manager.py#L1940)); a caller **cannot** set a dump folder per request (those fields belong to `ConfigureLoggingReq`, not the generate payload).

### INFO — Network egress from engine code: none beyond opt-in
**No telemetry/analytics SDKs** in the serving tree (sentry/posthog/wandb/datadog/segment/mixpanel/amplitude/bugsnag/rollbar sweep clean). OTLP tracing OFF (`enable_trace=False`, `--enable-trace` absent). Metrics are **pull-based** Prometheus `/metrics`, labels `{model_name, engine_type, tp_rank, pp_rank, moe_ep_rank, cache_source}` only, bodies are token counts/latencies — **no content**; `--enable-cache-report` adds cached-token counts. Startup warmup is an internal synthetic request; multimodal URL fetch not on the text-chat path; weights download is the pinned HF checkpoint only.

### INFO (residual) — `--trust-remote-code` with pinned revision
ON → arbitrary Python from the model repo executes in-process (full network/FS, unconstrainable by sglang). Mitigated by pinning `--revision 8f60817a…` (downloader pins the same SHA). Residual = trust in that specific [`QuantTrio/GLM-5.1-AWQ`](https://huggingface.co/QuantTrio/GLM-5.1-AWQ) revision's Python; not auditable here.

### INFO — The in-enclave patch is out of the serving/plaintext path (this build = base + patch)
The running engine (`glm51-sgl-awq-tp4-patched:local`) is this base image **plus one visible in-enclave build step**: an inline, fail-loud regex patch applying upstream [sglang#28305](https://github.com/sgl-project/sglang/pull/28305) (a fused qkv_a_proj `cat_dim` fix) to `python/sglang/srt/models/deepseek_common/deepseek_weight_loader.py`. That file is on the **weight-loading** path, not the serving/plaintext data path this review traced (HTTP entry → OpenAI serving → tokenizer manager → scheduler → detokenizer) — it rewrites how already-trusted checkpoint tensors are concatenated at load, and adds no logger, no I/O, and no network. The patch text is fully visible in the attested inner compose (`dockerfile_inline`, hash-pinned by the action log) and its `assert n == 1` turns any silent drift into a build failure. So the "this exact build" claim on this row holds for base **and** patch: the patch cannot introduce a plaintext log/persist/egress path. Its deployment-config framing (fail-loud, hash-pinned) is covered in the [measured-config audit](/manifests/measured/sha256-2c650eae81601afade86d1aa5ad898473b992081998026bb42ee1524ce99ee38.md) Check 3.

### Verdict: PRIVATE at deployed flags
On the measured launch command/env, the engine does **not** log, persist, or egress user plaintext: request logging disabled (`--log-requests` absent), every disk-dump feature off, prefix/KV cache RAM-only, metrics content-free counts, no analytics/tracing exporters active. Prompt/response content stays in process memory for the request's duration.

**Residuals (why not unconditional):** (1) **Unauthenticated `/configure_logging` (CRITICAL)** — the engine ships an open runtime switch to turn on full logging + disk dumps; its only guard is external proxy/network segmentation, outside the attested sglang config and unverified here (the flat `dstack_default` network makes co-resident reachability plausible). This should be closed inside the engine's own boundary (`--admin-api-key`, or attest the proxy path allowlist). (2) `--trust-remote-code` pinned but unaudited third-party Python. (3) a `sglang.private.*` exporter hook, if the base image bundles it, could add request exporters invisibly to this OSS tree. (4) the vllm-proxy/OHTTP front end and the otel→`telemetry.infra.near.ai` pipeline were out of scope; they carry sglang stdout, which matters only if #1 or `--log-requests` is ever activated.
