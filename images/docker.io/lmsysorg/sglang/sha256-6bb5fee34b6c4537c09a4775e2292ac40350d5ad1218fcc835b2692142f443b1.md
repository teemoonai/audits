### CRITICAL — `/configure_logging` is an unauthenticated runtime switch to enable full prompt+output logging and disk dumps
[`http_server.py:1513-1520`](https://github.com/sgl-project/sglang/blob/7de33ce806c12664b647604d61cf1403d2d18013/python/sglang/srt/entrypoints/http_server.py#L1513-L1520) exposes `GET/POST /configure_logging` at `@auth_level(AuthLevel.ADMIN_OPTIONAL)`. **With no `api_key` and no `admin_api_key` configured (the deployed state), `decide_request_auth` returns `AuthDecision(allowed=True)`** — [`auth.py:128-138`](https://github.com/sgl-project/sglang/blob/7de33ce806c12664b647604d61cf1403d2d18013/python/sglang/srt/utils/auth.py#L128-L138): `if auth_level == ADMIN_OPTIONAL: … else: return AuthDecision(allowed=True)`. The handler `configure_logging` ([`tokenizer_manager.py:1782-1804`](https://github.com/sgl-project/sglang/blob/7de33ce806c12664b647604d61cf1403d2d18013/python/sglang/srt/managers/tokenizer_manager.py#L1782-L1804)) accepts a `ConfigureLoggingReq` ([`io_struct.py:1818-1826`](https://github.com/sgl-project/sglang/blob/7de33ce806c12664b647604d61cf1403d2d18013/python/sglang/srt/managers/io_struct.py#L1818-L1826)) and can set at runtime: `log_requests=true`, `log_requests_level=3`, `dump_requests_folder=<path>`, `crash_dump_folder=<path>`. Level 3 → `max_length = 1 << 30` with no skip list ([`request_logger.py:229-230`](https://github.com/sgl-project/sglang/blob/7de33ce806c12664b647604d61cf1403d2d18013/python/sglang/srt/utils/request_logger.py#L229-L230), full input/output, no redaction); a dump folder → every finished request pickled to disk with prompt + output ([`tokenizer_manager.py:2458-2488`](https://github.com/sgl-project/sglang/blob/7de33ce806c12664b647604d61cf1403d2d18013/python/sglang/srt/managers/tokenizer_manager.py#L2458-L2488), dumps `state.obj` + `out_dict` to a `.pkl`).
- **Deployed status:** OFF (nothing has called it), but **flippable by anyone who can reach sglang's `0.0.0.0:8000` with zero credentials.** sglang is unauthenticated in the measured config; the only barrier is the front-end proxy's path filtering, which lives **outside** the measured launch config and was not verifiable here.
- **Activates on:** one HTTP POST. Same finding and rationale as the GLM-5.1 build's exemplar — the guard is external/unverified, so rated CRITICAL. Recommendation unchanged: close it inside the engine boundary (`--admin-api-key`) or attest the proxy path-allowlist.

`RequestLogger.log_received_request` / `log_finished_request` ([`request_logger.py:88-191`](https://github.com/sgl-project/sglang/blob/7de33ce806c12664b647604d61cf1403d2d18013/python/sglang/srt/utils/request_logger.py#L88-L191)) emit prompt text, decoded input, and output; at level ≥2 the serving layer additionally logs the raw OpenAI payload — but that call is itself gated: [`serving_base.py:88-90`](https://github.com/sgl-project/sglang/blob/7de33ce806c12664b647604d61cf1403d2d18013/python/sglang/srt/entrypoints/openai/serving_base.py#L88-L90) `if request_logger.log_requests and request_logger.log_requests_level >= 2:`. ### INFO (build-specific, item A) — `--enable-return-hidden-states` / `DSV4_RETURN_HIDDEN_STATES`: same egress channel, same actor, no new sink
The toggle is doubly gated. **Server gate:** without `--enable-return-hidden-states`, a client request carrying `return_hidden_states=true` is **rejected** — [`tokenizer_manager.py:1019-1026`](https://github.com/sgl-project/sglang/blob/7de33ce806c12664b647604d61cf1403d2d18013/python/sglang/srt/managers/tokenizer_manager.py#L1019-L1026) raises `ValueError("The server is not configured to return the hidden states…")`. **Per-request gate:** `return_hidden_states` defaults `False` ([`protocol.py:340`](https://github.com/sgl-project/sglang/blob/7de33ce806c12664b647604d61cf1403d2d18013/python/sglang/srt/entrypoints/openai/protocol.py#L340)); when set, `process_hidden_states_from_ret` returns **only the last token's** hidden state ([`openai/utils.py:54-76`](https://github.com/sgl-project/sglang/blob/7de33ce806c12664b647604d61cf1403d2d18013/python/sglang/srt/entrypoints/openai/utils.py#L54-L76): `hidden_states[-1] if len(hidden_states) > 1 else []`), which is attached to the response returned to **the same requesting client** ([`serving_chat.py:1396`](https://github.com/sgl-project/sglang/blob/7de33ce806c12664b647604d61cf1403d2d18013/python/sglang/srt/entrypoints/openai/serving_chat.py#L1396), [`serving_completions.py:549`](https://github.com/sgl-project/sglang/blob/7de33ce806c12664b647604d61cf1403d2d18013/python/sglang/srt/entrypoints/openai/serving_completions.py#L549), and the streaming chunks at `serving_chat.py:1172-1194`).
- **Trace conclusion:** enabling it creates **no new data path and no new actor.** Hidden states are a derived representation of the requester's *own* prompt/generation, flowing back over the *same* HTTP response channel to the *same* caller. Nothing is logged, persisted, or sent to a third party by this feature. It is not a plaintext leak even when on.
- **Residual (honest):** whether `DSV4_RETURN_HIDDEN_STATES` sits in the node's measured `allowed_envs` — i.e. whether an operator can flip `--enable-return-hidden-states` without changing the hardware measurement — is a **manifest question, not answerable from this source tree; INCONCLUSIVE here.** Even if it is operator-flippable, the privacy impact is bounded as above (same-client egress only). One marginal note: hidden states live in `out["meta_info"]["hidden_states"]` and are **not** in the finished-request logger's `out_skip_names` (`{"text","output_ids","embedding"}`, [`request_logger.py:213,226`](https://github.com/sgl-project/sglang/blob/7de33ce806c12664b647604d61cf1403d2d18013/python/sglang/srt/utils/request_logger.py#L213)), so they would appear in request logs at *any* level — but only if `--log-requests` is already on, which is itself the HIGH finding above.

### Verdict: PRIVATE at deployed flags
On the measured launch command/env, the engine does **not** log, persist, or egress user plaintext: request logging disabled (`--log-requests` absent → every logger early-returns), every disk-dump feature off (crash/dump/tensor/metrics-file all unset, folders empty), prefix/KV cache RAM-only (including the deployed `SGLANG_ENABLE_UNIFIED_RADIX_TREE`), metrics content-free pull-based counters, no analytics/tracing exporters active. The two build-specific additions are clean: **EAGLE spec-decode adds no content sink**, and **the hidden-states toggle, even if enabled, returns data only to the requesting client over the normal response channel — no new actor.** Prompt/response content stays in process memory for the request's duration.

**Residuals (why not unconditional):**
1. **Unauthenticated `/configure_logging` (CRITICAL)** — the engine ships an open runtime switch to turn on full logging + disk dumps; its only guard is the external proxy/network, outside the attested sglang config and unverified here. Close inside the engine boundary (`--admin-api-key`) or attest the proxy path-allowlist.
2. **`DSV4_RETURN_HIDDEN_STATES` in `allowed_envs`? — INCONCLUSIVE** (manifest question). Impact is bounded (same-client egress only) regardless.
3. `--trust-remote-code` pinned (`--revision 553034d7…`) but the checkpoint's Python is unaudited third-party code.
4. The front-end proxy / OHTTP layer and the off-box log pipeline were out of scope; they carry sglang stdout, which matters only if #1 or `--log-requests` is ever activated.
