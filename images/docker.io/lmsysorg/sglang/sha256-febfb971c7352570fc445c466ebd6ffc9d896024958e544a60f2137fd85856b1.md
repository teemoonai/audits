# SGLang inference engine (Qwen3.8-27B) — Privacy Audit

> Part of the near.ai inference-path privacy audit. Method: [/notes/method.md](/notes/method.md).

**Image:** `lmsysorg/sglang@sha256:febfb971c7352570fc445c466ebd6ffc9d896024958e544a60f2137fd85856b1` (nightly-dev-20260814-c4271c3f, 2026-08-14)
**Source:** `sgl-project/sglang` @ `c4271c3fe1262fc2adbd162c33b25de5255251c5`
**Role:** the inference engine — the one process legitimately entitled to see message plaintext. It sits behind `nearaidev/vllm-proxy-rs` (the E2EE/OHTTP terminator) behind nginx; engine port 8000 is not host-published but is reachable on the `external: true` shared Docker network `dstack_default`.

**Verdict:** At the deployed launch flags, no plaintext copy is written to any log, file, cache, or model-external network destination in steady-state operation. Request logging is off and set to its safest level (`--log-requests-level 0`, genuinely consumed on this LLM path), request/crash dumping is off, no engine telemetry is emitted, and Prometheus labels are content-free. Three paths keep this short of "cannot happen":

1. an **unauthenticated `/configure_logging` endpoint** (CRITICAL, deployed ON) — one HTTP POST turns on verbatim prompt+output logging and arbitrary-path request pickling, no restart;
2. a **watchdog hang-time dump** (HIGH, deployed ON) — full prompt and output token IDs of the in-flight batch (plus `sampling_params`) written to stdout at ERROR on an engine hang, undisableable, and now armed at the **300 s** default because this recipe does not pass `--watchdog-timeout` for the Qwen service (the base command pinned 1800 s);
3. a **request-driven media fetch** (MEDIUM, deployed ON) — Qwen3.8-27B-FP8 at the pinned revision is **multimodal** (vision + video), so an image/audio/video URL in a chat request is fetched by the engine with **no domain allowlist** and redirects followed by default.

The amplifier for findings 1 and 2: this recipe carries **its own `otelcol-contrib`**, which ships engine stdout verbatim to `https://telemetry.infra.near.ai` on **all 3 hosts**; a third-party Datadog leg (`us3.datadoghq.com`) is additionally present or not depending on each node's measured harness (settled on the manifest pages, not here).

### HIGH (deployed: ON) — watchdog hang dump writes the full prompt and output token IDs of the in-flight batch to stdout at ERROR, undisableable, armed at the 300 s default — sink: log (egress to near.ai on every host)

No attacker, no config change. On any forward-batch stall the scheduler watchdog runs `dump_info` before crashing:

- [`watchdog.py:149-150`](https://github.com/sgl-project/sglang/blob/c4271c3fe1262fc2adbd162c33b25de5255251c5/python/sglang/srt/utils/watchdog.py#L149) — `if self.dump_info is not None and (info_msg := self.dump_info()):` / `logger.error(f"{self.debug_name} debug info:\n{info_msg}")`

`dump_info` returns the in-flight batch's requests:

- [`invariant_checker.py:465-473`](https://github.com/sgl-project/sglang/blob/c4271c3fe1262fc2adbd162c33b25de5255251c5/python/sglang/srt/managers/scheduler_components/invariant_checker.py#L465) — `f"{scheduler.cur_batch_for_debug.reqs=}\n" + "\n".join(messages)` (line 473).

`cur_batch_for_debug.reqs` is a list of `Req`, whose `__repr__` interpolates the content:

- [`schedule_batch.py:1844-1850`](https://github.com/sgl-project/sglang/blob/c4271c3fe1262fc2adbd162c33b25de5255251c5/python/sglang/srt/managers/schedule_batch.py#L1844) — `f"input_ids={self.origin_input_ids}, output_ids={self.output_ids}, "` plus `{self.grammar=}` and `{self.sampling_params=}`.

That is the complete prompt token sequence and complete generated token sequence for every request in the batch — plaintext after one `decode()` with the public Qwen tokenizer — plus the client-supplied `sampling_params`. There is no flag, env var, or verbosity level that suppresses it; `--log-requests` is irrelevant.

**Trigger armed at 300 s.** `watchdog_timeout` defaults to **300** ([`server_args.py:1222-1226`](https://github.com/sgl-project/sglang/blob/c4271c3fe1262fc2adbd162c33b25de5255251c5/python/sglang/srt/server_args.py#L1222)) and the Qwen anchor does **not** pass `--watchdog-timeout`, so the hard watchdog fires after a 5-minute forward stall — not the 30 minutes the base v0.5.14 command pinned. (The recipe *does* pin `--watchdog-timeout 1800` for the DSV4 and GLM siblings, but not for Qwen.) The soft watchdog (same `dump_info`, no crash) stays off — `soft_watchdog_timeout` defaults to `None` ([`server_args.py:1227-1231`](https://github.com/sgl-project/sglang/blob/c4271c3fe1262fc2adbd162c33b25de5255251c5/python/sglang/srt/server_args.py#L1227)) and is auto-set only in CI ([`server_args.py:8531-8533`](https://github.com/sgl-project/sglang/blob/c4271c3fe1262fc2adbd162c33b25de5255251c5/python/sglang/srt/server_args.py#L8531)).

Severity stays HIGH rather than CRITICAL: the trigger is an availability incident, not a remote-inducible event, and the blast radius is the in-flight batch (bounded by `--max-running-requests 64`). It is not LOW: unconditional, undisableable, lands in a stream that leaves the machine to near.ai's telemetry backend on every one of these 3 hosts, and requires no misconfiguration. On a TP1 27B model a genuine 5-minute forward stall is less routine than the base page's 30-minute GPU-wedge scenario, but the window is now wider (fires at a shorter stall).

### Verdict: PRIVATE at the deployed flags — three live paths short of "cannot happen", on a self-asserted nightly build

At the flags actually deployed, I found no path by which message plaintext reaches a log, file, cache, or model-external destination during normal operation. Request logging is off and pinned to its safest level, request/crash dumping is off, the engine emits no telemetry of its own, Prometheus labels are content-free, `--trust-remote-code` has nothing to execute at the pinned revision, and nothing request-derived is written to the mounted volumes. `sglang serve` genuinely consumes `--log-requests-level 0` on the LLM dispatch path — the §7 silent-drop defect does not apply here. That is a real result and it is the state the engine is in right now.

But "off" is not "cannot happen," and three things keep this from a clean bill:

1. The **unauthenticated `/configure_logging` endpoint** is present and unchanged at `c4271c3f`. One unauthenticated POST — for which SGLang ships a client with prompt-logging defaults — flips this engine from logging nothing to logging every prompt and completion verbatim, and can begin pickling full request/response pairs to any path. No restart, no attestation-visible event. The project gates the comparable HiCache endpoint properly, so this is an omission, not a design position.
2. The **watchdog dump** is unconditional and undisableable, and here fires at the **300 s** default because this recipe does not pass `--watchdog-timeout` for the Qwen service. On any forward-batch stall the full prompt and output token IDs of the in-flight batch (plus `sampling_params`) are written to stdout at ERROR.
3. The **request-driven media fetch** is reachable because Qwen3.8-27B is multimodal at the pinned revision: a URL in a chat request is fetched with no allowlist and redirects on — a model-external, request-driven egress and an SSRF/`file://`-read primitive from inside the plaintext process.

The first two terminate in stdout, and this recipe's own `otelcol-contrib` ships that stdout verbatim to `https://telemetry.infra.near.ai` on **all 3 hosts** with no redaction; where a Datadog agent is additionally measured on the node, it goes to a third-party US SaaS as well. Layered on top: the identity is a **self-asserted nightly dev build**, 3 days old, carrying a prebuilt nightly FlashInfer pinned only in a builder label — so the confidence in "these are the bytes reviewed" is lower here than on the release-tagged pages, even though the source-level findings are identical to v0.5.16. The single change that most improves the posture is passing `--admin-api-key` — one flag, already implemented upstream, that closes the CRITICAL and the other open admin routes at once.

### Residuals

1. **`/configure_logging` is unauthenticated** and can enable full prompt/output logging and arbitrary-path request dumping at runtime — confirmed at this exact commit.
2. **Whether that endpoint is reachable from outside the CVM depends on `nearaidev/vllm-proxy-rs`** — a different image; nginx applies no path filter. A residual, not a mitigation.
3. **`dstack_default` is an `external: true` shared network** — any co-resident container can reach engine port 8000 directly.
4. **The watchdog prompt dump cannot be disabled by configuration** — it needs an upstream source change; and here it is armed at 300 s, not 1800 s.
5. **The recipe's own otel collector ships container stdout off-box to near.ai on all 3 hosts with no redaction** — every log-writing finding above is an egress finding; a node-measured Datadog agent adds a third-party US SaaS destination where present.
6. **The media-fetch path has no allowlist** — request-driven egress + SSRF + local-file read, on by default because Qwen3.8-27B is multimodal.
7. **CUDA core dumping is enabled in code by default**, blocked only by the absence of `CUDA_ENABLE_USER_TRIGGERED_COREDUMP=1`.
8. **Image identity is self-asserted and this is a nightly dev build** — no signed provenance attestation ties this digest to `c4271c3f`; the OCI labels (including the tag and the FlashInfer pin) are builder-supplied.
9. **The prebuilt nightly FlashInfer** named in the labels was not inspected; a native kernel library that operates on prompt-derived activations, pinned only in a label.
10. **The image filesystem was not inspected** — the `sglang.private.*` metrics hook and the external multimodal-processor plugin point are silent hooks a modified image could populate without touching the OSS source reviewed here.
