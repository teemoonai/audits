# SGLang inference engine (GLM-5.2 W4AFP8, TP8 / 1M context) — Privacy Audit

> Part of the near.ai inference-path privacy audit. Method: [/notes/method.md](/notes/method.md).

**Image:** `lmsysorg/sglang@sha256:1c64fde976bdf0d56474a30bccbcfc19667e5b3ab34c826a534c9d6aaca41212` (v0.5.13.post1, 2026-06-15)
**Source:** `sgl-project/sglang` @ `85fd90072d1a9f2432842b03588f63b745e524e4`
**Location:** one TP8 replica across all 8 GPUs inside the CVM, behind `nearaidev/vllm-proxy-rs@sha256:b183677a…` (the E2EE/OHTTP terminator) behind nginx. Engine port 8000 is **not** published to the host — reachable only on the Docker network `dstack_default`, which is declared `external: true`.
**Role:** the inference engine. It is the one process legitimately entitled to see message plaintext.
**Verdict:** At the deployed launch flags, no plaintext copy is written to any log, file, cache, or network destination in steady-state operation. Two paths keep this short of "cannot happen", and both are the same ones this repo has now found at every audited SGLang build: an **unauthenticated `/configure_logging` endpoint** that turns on full prompt+output logging *and* arbitrary-path request dumping with no restart, and a **watchdog debug dump** that writes the full prompt and output token IDs of the in-flight batch to stdout on any engine hang, with no flag to disable it. On this host the second one matters more than anywhere else in the fleet: it is the 1M-context tier, running `--max-running-requests 256`.

So the trigger requires a genuine 30-minute engine hang.

**Why this host is the worst case in the fleet.** Two deployed numbers set the blast radius, and both are larger here than anywhere else audited: `--max-running-requests 256` (compose line 146) bounds the in-flight batch at 256 requests rather than 96, and `--context-length 1048576` (compose line 149) means those requests may carry up to a million prompt tokens each. The requests most likely to be in flight when it hangs are the largest documents users send.

Cold start is documented at 35–60 minutes (compose lines 49–50, 92–93), which is itself long enough to interact with a 1800s watchdog window.

Severity is HIGH rather than CRITICAL because the trigger is an availability incident rather than something a remote party can induce on demand, and the blast radius is the in-flight batch rather than all traffic. It is not lower, because it is unconditional, undisableable, lands in a stream that leaves the machine, and requires no misconfiguration whatsoever.

### MEDIUM (deployed: ON) — engine stdout is shipped verbatim off-box, with no redaction anywhere in the pipeline

This is the amplifier that converts either finding above from "a local file" into "egress". It lives in the compose file, which *is* attested, so it is in scope.

The `otelcol-contrib` sidecar mounts the host's Docker log directory read-only (compose line 351):

```
- /var/lib/docker/containers:/var/lib/docker/containers:ro
```

and tails every container's JSON log file (compose lines 390–391):

```yaml
filelog/docker_containers:
  include: [/var/lib/docker/containers/*/*-json.log]
```

The raw log line is moved into the record body unmodified (compose lines 404–407: `type: move`, `from: attributes.log`, `to: body`). The `logs/app` pipeline then exports to a remote gateway (compose lines 577–581, 594–597):

```yaml
otlphttp/gateway:
  endpoint: https://telemetry.infra.near.ai
  headers:
    Authorization: "Bearer $${env:MONITORING_INGEST_TOKEN}"
```

The only filter is `filter/app_logs` (compose lines 546–555), which drops records with neither a `model` nor a `deployment` attribute and drops five infrastructure services by name. The sglang container carries a `com.datadoghq.ad.logs` label with `model:` and `deployment:` tags (compose line 278), whose values the filelog operators extract into exactly those attributes (compose lines 419–426), so its logs match and are **kept**. There is no `transform` that scrubs, hashes, truncates or pattern-matches the body — the only log-touching transform sets service/source metadata (compose lines 534–544).

So the full chain is: *anything the engine prints to stdout or stderr* -> Docker `json-file` driver (compose lines 95–100) -> otel filelog receiver -> `https://telemetry.infra.near.ai`. Both the CRITICAL and HIGH findings terminate here.

Note also that the TP8 scheduler ranks are subprocesses of the container's main process and inherit its stdout/stderr, so scheduler-side output — including the watchdog dump above — travels the same path.

At deployed flags nothing prompt-derived is written to that stream, which is why this is MEDIUM and not higher. But the absence of any redaction stage means the pipeline provides zero defence in depth: it is a straight pipe from the engine's log calls to an off-box collector.

### LOW (deployed: ON) — request content can be echoed back in a 400 validation error body

For a malformed request, the validation handler builds its message from both the exception string and `exc.errors()`:

[`http_server.py:463-467`](https://github.com/sgl-project/sglang/blob/85fd90072d1a9f2432842b03588f63b745e524e4/python/sglang/srt/entrypoints/http_server.py#L463) — `exc_str = str(exc)` / `errors_str = str(exc.errors())` / `if errors_str and errors_str != exc_str:` / `message = f"{exc_str} {errors_str}"`

This is returned to the caller in the response body — i.e. back down the same E2EE channel to the user — and is not written to any log by this code. So it is not exfiltration on its own. It becomes one only if an intermediary logs response bodies; the proxy is out of scope here, so I cannot rule that out.

Related: one assertion carries a full request repr — [`grammar_manager.py:168`](https://github.com/sgl-project/sglang/blob/85fd90072d1a9f2432842b03588f63b745e524e4/python/sglang/srt/constrained/grammar_manager.py#L168) — `assert isinstance(req.grammar, futures.Future), f"{req=}"`. `f"{req=}"` invokes the same `Req.__repr__` that renders `origin_input_ids` and `output_ids`. ### Verdict: private at the deployed flags — with two live paths that stop it short of "cannot happen"

At the flags actually deployed, I found no path by which message plaintext reaches a log, file, cache, database or network destination during normal operation. Request logging is off and pinned to its safest verbosity, request dumping and crash dumping are off, the engine emits no telemetry of its own, Prometheus labels are content-free, no media fetch path exists for this text-only architecture, `--trust-remote-code` has nothing to execute at the pinned revision, and nothing request-derived is written to the persisted volumes.

That is a real result, and it is the state the engine is in right now. But "off" is not "cannot happen".

The first live path is the **unauthenticated `/configure_logging` endpoint**. Confirmed from source at `85fd9007`, with the same shape as at `49e384ce`: `ADMIN_OPTIONAL` degrades to "allow" when no keys are set, and with no `ADMIN_FORCE` route anywhere in the tree the auth middleware is never even installed. One unauthenticated HTTP POST — for which SGLang ships a client script whose defaults are level 3 and a dump folder — flips this engine from logging nothing to logging every prompt and completion verbatim, and can additionally begin pickling full request/response pairs to any path on the filesystem, including a persisted volume. No restart, no config change, no attestation-visible event. The nearby control the project *did* get right, the explicit `admin_api_key` check on the HiCache storage endpoints, shows this is an omission rather than a design position.

The second is the **watchdog debug dump**, which is conditional on nothing. On any 30-minute engine hang, the full prompt and output token IDs of every in-flight request are written to stdout at ERROR level, with no flag to turn it off. On this host that means up to 256 requests carrying up to a million prompt tokens each — and this is precisely the host `cloud-api` routes the fleet's longest inputs to. The compose file's own header documents this hardware OOMing, taking Xid 31 MMU faults, and wedging the whole TP8 group via NCCL heartbeat.

Both terminate in the same place: container stdout is tailed by an otel sidecar mounting the host Docker log directory and exported verbatim to `https://telemetry.infra.near.ai`, with no redaction stage anywhere in the pipeline.

The single change that would most improve this posture is passing `--admin-api-key` to the engine. It costs one flag, it is already fully implemented upstream, and it converts `/configure_logging` — along with every other currently-open administrative route — from open to authenticated.

### Residuals

1. **`/configure_logging` is unauthenticated and can enable full prompt/output logging and arbitrary-path request dumping at runtime.** No restart, no attestation change, no operator-visible artifact other than the log volume itself. Confirmed present at this exact commit.
2. **There is no path allowlist in front of it.** nginx applies none (bare `location /`, compose lines 822–833 and 918–929), and the repo's proxy reviews establish the proxy applies none either. **That is a residual, not a mitigation** — and a control in an unattested proxy would be strictly weaker than an API key inside the attested engine in any case. I inherited the proxy result from the [`b0c5cd07` page](/images/docker.io/nearaidev/vllm-proxy-rs/sha256-b0c5cd0786b19dfa46144107be15e340b7a338b1c341d02ffa994c9f1ea77dfd.md) and the [README correction](README.md) rather than re-deriving it at the `b183677a`/`372824b4` tree deployed here.
3. **`dstack_default` is an `external: true` shared Docker network.** Any container on that network on the same host — including ones from other compose projects, outside this file's attestation — can reach engine port 8000 directly, bypassing nginx and the proxy entirely.
4. **The watchdog prompt dump cannot be disabled by configuration,** and this host has the fleet's largest in-flight batch and context window.
5. **Container stdout leaves the machine with no redaction.** Every finding above that writes to a log is therefore an egress finding, not a local-disk finding.
6. **CUDA core dumping is enabled in code by default** and blocked only by the absence of `CUDA_ENABLE_USER_TRIGGERED_COREDUMP=1`. A debugging session that adds that variable would begin writing GPU memory — KV cache and activations — to disk on crash.
7. **Image identity is builder-asserted.** The labels are registry-verifiable at this digest and corroborated by an upstream Actions run at the same commit, but no signed provenance ties these bytes to that tree (`GET /repos/sgl-project/sglang/attestations/sha256:1c64fde9…` -> 404). Everything here inherits that assumption.
8. **The image filesystem was not inspected.** The `sglang.private.*` metrics-exporter hook and the `SGLANG_EXTERNAL_MM_MODEL_ARCH` hook are silent plugin points a modified image could populate without any change to the OSS source reviewed here.
9. **The proxy's own egress is out of scope here** but worth naming: the `proxy-glm52` service is handed `WEB_CONTEXT_SEARCH_URL` / `WEB_CONTEXT_SEARCH_API_KEY` (compose lines 236–237), an opt-in per-request web-search egress analysed in the [`b183677a` proxy page](/images/docker.io/nearaidev/vllm-proxy-rs/sha256-b183677a5d32267539b9b21ec45327a4f3be0a013afeb608c68c4d76e9472e36.md). It does not involve this image.
