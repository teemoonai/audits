# SGLang inference engine (Qwen3.x) — Privacy Audit

> Part of the near.ai inference-path privacy audit. Method: [/notes/method.md](/notes/method.md).

**Image:** `lmsysorg/sglang@sha256:984699c298a95b73c469b2191403ddc85fd780506e13c39c4afff3845e27bc6c` (v0.5.16-cu129, 2026-07-24)
**Source:** `sgl-project/sglang` @ `fdebc938f7f4d16fe6b9f55dcd9a767cf0899ea1`
**Role:** the inference engine — the one process legitimately entitled to see message plaintext. It sits behind `nearaidev/vllm-proxy-rs` (the E2EE/OHTTP terminator) behind nginx; engine port 8000 is not host-published but is reachable on the `external: true` shared Docker network `dstack_default`.

**Verdict:** At the deployed launch flags, no plaintext copy is written to any log, file, cache, or model-external network destination in steady-state operation. Request logging is off and set to its safest level, request/crash dumping is off, no engine telemetry is emitted, and Prometheus labels are content-free. Three paths keep this short of "cannot happen":

1. an **unauthenticated `/configure_logging` endpoint** (CRITICAL, deployed ON) — one HTTP POST turns on verbatim prompt+output logging and arbitrary-path request pickling, no restart;
2. a **watchdog hang-time dump** (HIGH, deployed ON) — full prompt and output token IDs of the in-flight batch written to stdout at ERROR on an engine hang, undisableable, and now armed at the **300 s** default rather than the base command's 1800 s;
3. a **request-driven media fetch** (MEDIUM, deployed ON, **new**) — because every model served on this image in these recipes is **multimodal**, an image/audio/video URL in a chat request is fetched by the engine with **no domain allowlist** and redirects followed by default. The base page's engine (text-only GLM) had no reachable fetch path; this one does.

Findings 1 and 2 terminate in stdout, which the inner recipe's own `otelcol-contrib` ships off-box to near.ai's telemetry gateway on **every** node; datadog-bearing nodes additionally carry it to a third-party US SaaS, while the small-models node's measured harness is fail-closed (see the MEDIUM egress finding). There is no redaction on any collector.

### Verdict: PRIVATE at the deployed flags — three live paths short of "cannot happen"

At the flags actually deployed across all three recipes, I found no path by which message plaintext reaches a log, file, cache, or model-external destination during normal operation. Request logging is off and pinned to its safest level, request/crash dumping is off, the engine emits no telemetry of its own, Prometheus labels are content-free, and nothing request-derived is written to the mounted volumes. `sglang serve` genuinely consumes `--log-requests-level 0` on the LLM dispatch path — the §7 silent-drop defect does not apply here. That is a real result and it is the state the engine is in right now.

But "off" is not "cannot happen," and three things keep this from a clean bill:

1. The **unauthenticated `/configure_logging` endpoint** is present and unchanged at `fdebc938`. One unauthenticated POST — for which SGLang ships a client with prompt-logging defaults — flips this engine from logging nothing to logging every prompt and completion verbatim, and can begin pickling full request/response pairs to any path. No restart, no attestation-visible event. The project gates the comparable HiCache endpoint properly, so this is an omission, not a design position.
2. The **watchdog dump** is unconditional and undisableable, and now fires at the **300 s** default rather than 1800 s. On any forward-batch stall the full prompt and output token IDs of the in-flight batch (plus `sampling_params`) are written to stdout at ERROR.
3. The **request-driven media fetch** is new here and on by default: every model served on this image in these recipes is multimodal, and a URL in a chat request is fetched with no allowlist and redirects on — a model-external, request-driven egress and an SSRF/`file://`-read primitive from inside the plaintext process.

The first two terminate in stdout, and every node ships engine stdout off-box: the inner recipe's own `otelcol-contrib` keeps model-tagged app logs and exports them to near.ai's telemetry gateway with no redaction, on all three recipes. On the datadog-bearing majority of these 13 hosts a measured Datadog agent additionally carries the same stdout to a third-party US SaaS; on the small-models node the measured layer is genuinely fail-closed, so there the off-box path is near.ai's gateway alone. Either way there is no redaction stage anywhere, so print-discipline is the whole defence. The single change that most improves the posture is passing `--admin-api-key` — one flag, already implemented upstream, that closes the CRITICAL and ~30 other open admin routes at once.

### Residuals

1. **`/configure_logging` is unauthenticated** and can enable full prompt/output logging and arbitrary-path request dumping at runtime — confirmed at this exact commit.
2. **Whether that endpoint is reachable from outside the CVM depends on `nearaidev/vllm-proxy-rs`** — a different image; nginx applies no path filter. A residual, not a mitigation.
3. **`dstack_default` is an `external: true` shared network** — any co-resident container can reach engine port 8000 directly.
4. **The watchdog prompt dump cannot be disabled by configuration** — it needs an upstream source change.
5. **Container stdout leaves the machine on every node with no redaction** — the inner recipe's own `otelcol-contrib` ships app logs to `telemetry.infra.near.ai` on all three recipes, so every log-writing finding above is an egress finding to near.ai's backend; on datadog-bearing nodes a measured Datadog agent additionally carries it to a third-party US SaaS. Only the measured harness (not the recipe collector) differs by node.
6. **The media-fetch path has no allowlist** — request-driven egress + SSRF + local-file read, on by default because these models are multimodal.
7. **The two `dsv4-qwen36-gemma4` Qwen3.6 services run `--trust-remote-code` unpinned** — running bytes can drift; a future repo push could execute code in-enclave.
8. **CUDA core dumping is enabled in code by default**, blocked only by the absence of `CUDA_ENABLE_USER_TRIGGERED_COREDUMP=1`.
9. **Image identity is self-asserted** — no signed provenance attestation ties this digest to `fdebc938`; the OCI labels are builder-supplied.
10. **The image filesystem was not inspected** — the `sglang.private.*` metrics hook and the external multimodal-processor plugin point are silent hooks a modified image could populate without touching the OSS source reviewed here.
