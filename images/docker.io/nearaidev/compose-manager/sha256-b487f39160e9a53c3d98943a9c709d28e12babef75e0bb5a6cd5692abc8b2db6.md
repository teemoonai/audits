# compose-manager (+ launcher) — Privacy / Supply-Chain Audit

> Part of the near.ai inference-path privacy re-audit (Fable-only, 2026-07-15).
> Method: [`/notes/method.md`](/notes/method.md) · Architecture: [`ARCHITECTURE.md`](/notes/ARCHITECTURE.md) · Index: [`README.md`](README.md)

**Images:** `nearaidev/compose-manager` @ `3d64349a6c71…`, `nearaidev/compose-manager-launcher` @ `9a035b2fadff…`
**Source:** [`github.com/nearai/compose-manager`](https://github.com/nearai/compose-manager/tree/3d64349a6c71a0711f9dd4f9d2897eefa4a0d8bc) (both; `3d64349` is one commit ahead of `9a035b2` — the diff is 2 lines in `dashboard/index.html`, so no attestation-relevant delta).
**Location:** Model node CVM.
**Role:** the deployer — fetches the inner compose and runs `docker compose pull/build/up`. Never on the `/v1/chat/completions` path, but it controls **what code handles your plaintext**, so its integrity is a supply-chain question.
**Verdict:** **COMPROMISABLE (bounded)** — a caller-supplied `env` map is applied to the deployed stack but never hashed into attestation.

---

## Audit prompt

```text
Defensive privacy/supply-chain audit (authorized). The component deploys the code
that handles user plaintext, so the question is: can an operator change WHAT RUNS
(or its env/flags) without the change showing up in remote attestation?

TARGET: compose-manager (model-node deployer), manager @ 3d64349a6c71 and launcher
@ 9a035b2fadff. Cross-reference the attested inner compose it deploys:
cvm-compose-files/prod/GLM-5.1-SGL-AWQ-TP4.yaml @ c545c95545db.

LOOK FOR (cite file:line + one-line quote):
1. What it launches and from where; pinned how (commit? hash?).
2. Attestation binding: what gets hashed/recorded and WHEN relative to any mutation.
   Is any caller/operator-supplied input (env map, overrides) applied AFTER the
   attested hash is computed, and is that input itself hashed/recorded anywhere?
3. Image verification: cosign checks on images it runs; any flag that skips verification.
4. Action log integrity: append-only/tamper-evident, or a rewritable file?
5. Env-injection reachability against the REAL attested compose — are engine image
   digests and launch commands literal or ${VAR}-parameterized? Which ${VAR}s are
   privacy-relevant (logging flags, telemetry endpoints, tool/search API endpoints)?
6. Content exposure: does compose-manager itself ever see or log message content?
7. Network egress and update paths.

RULES: separate MECHANISM (what the code permits) from EFFECTIVE RISK (reachable
given the attested compose + allowed_envs); report uncertainty explicitly.
OUTPUT: findings CRITICAL/HIGH/MEDIUM/INFO labeled mechanism vs effective; verdict
(TRUSTWORTHY / COMPROMISABLE / INCONCLUSIVE) with exact residual attack surface.
```

## Results

**Files reviewed:** [`compose-manager/src/main.rs`](https://github.com/nearai/compose-manager/blob/3d64349a6c71a0711f9dd4f9d2897eefa4a0d8bc/src/main.rs) (3166 lines — the deploy HTTP service), [`launcher/launcher.sh`](https://github.com/nearai/compose-manager/blob/9a035b2fadfff19221c3c441c9fa4b7e432919d2/launcher/launcher.sh) (image self-updater + cosign gate), [`launcher/Dockerfile`](https://github.com/nearai/compose-manager/blob/9a035b2fadfff19221c3c441c9fa4b7e432919d2/launcher/Dockerfile), [`README.md`](https://github.com/nearai/compose-manager/blob/3d64349a6c71a0711f9dd4f9d2897eefa4a0d8bc/README.md), and the real attested inner compose. `git diff 9a035b2 3d64349` = only `dashboard/index.html` (2-line log-selector UI); the "launcher" is the in-repo `launcher/` self-updater, identical in both — treated as one system.

### CRITICAL (mechanism) / HIGH (effective) — Caller-supplied `env` map is applied AFTER the attested hash and is never recorded or hashed anywhere a verifier can see
**Mechanism.** `POST /compose/up` accepts a free-form `env: HashMap<String,String>` (`ComposeRequest`, [`main.rs:533`](https://github.com/nearai/compose-manager/blob/3d64349a6c71a0711f9dd4f9d2897eefa4a0d8bc/src/main.rs#L533)). The attested hash covers the compose-file **content only** — `file_sha256 = SHA256(content)` ([`main.rs:1392`](https://github.com/nearai/compose-manager/blob/3d64349a6c71a0711f9dd4f9d2897eefa4a0d8bc/src/main.rs#L1392)). The env map is then written to a temp file and passed as the **last** `--env-file` to `docker compose up` (`write_temp_env_file` [`main.rs:1407-1414`](https://github.com/nearai/compose-manager/blob/3d64349a6c71a0711f9dd4f9d2897eefa4a0d8bc/src/main.rs#L1407-L1414); appended last in `build_compose_cmd` [`:1261-1266`](https://github.com/nearai/compose-manager/blob/3d64349a6c71a0711f9dd4f9d2897eefa4a0d8bc/src/main.rs#L1261-L1266)), so per-request env **overrides** the sealed base secrets. The recorded `DeploymentAction` ([`:319-341`](https://github.com/nearai/compose-manager/blob/3d64349a6c71a0711f9dd4f9d2897eefa4a0d8bc/src/main.rs#L319-L341)) has fields `{timestamp, action, tag, commit, file, file_sha256, services, container, image}` — **no env field**. Attestation hashes only the action log into TDX `report_data` ([`:1780-1789`](https://github.com/nearai/compose-manager/blob/3d64349a6c71a0711f9dd4f9d2897eefa4a0d8bc/src/main.rs#L1780-L1789)). `validate_env_vars` ([`:594-604`](https://github.com/nearai/compose-manager/blob/3d64349a6c71a0711f9dd4f9d2897eefa4a0d8bc/src/main.rs#L594-L604)) enforces only key-format + no-newline — **no allow-list; any variable name/value is accepted.** So a caller with `BEARER_TOKEN` can inject arbitrary interpolation values; a verifier reading `/v1/attestation/report` sees `file_sha256` (compose text with literal `${WEB_CONTEXT_SEARCH_URL}` etc.) but **zero visibility into the substituted values**.

**Effective in this deployment.** The attested prod compose is `${VAR}`-parameterized (22 vars). Reachable, privacy-relevant, NOT bound in attestation:
- **`${WEB_CONTEXT_SEARCH_URL}` + `${WEB_CONTEXT_SEARCH_API_KEY}`** → injected into `proxy-glm51` env (prod [yaml:255-256](https://github.com/nearai/cvm-compose-files/blob/c545c95545dba47d8bea293aaae317089ea52f4d/prod/GLM-5.1-SGL-AWQ-TP4.yaml#L255-L256)). Redirecting the URL to an attacker endpoint **exfiltrates user-prompt-derived search queries with no change to `file_sha256` or the action log — the sharpest residual leak.**
- Auth-token vars (`PROXY_TOKEN`, `FUSION_INTERNAL_BEARER_TOKEN`, `MODEL_PROXY_TOKEN`, `CLOUD_API_USAGE_TOKEN`, `MONITORING_INGEST_TOKEN`, `HUGGING_FACE_HUB_TOKEN`) — substitutable, but the endpoints they authenticate to are **literal**, so this is credential-substitution, not a direct plaintext redirect. `FUSION_ENABLED` toggles a proxy feature (semantics unverified).

**Mitigating — the primary plaintext path is NOT env-redirectable:** engine image digests are pinned literals (`sglang…@sha256:aac6b2…` [yaml:67](https://github.com/nearai/cvm-compose-files/blob/c545c95545dba47d8bea293aaae317089ea52f4d/prod/GLM-5.1-SGL-AWQ-TP4.yaml#L67), `vllm-proxy-rs@sha256:b18367…` [yaml:45](https://github.com/nearai/cvm-compose-files/blob/c545c95545dba47d8bea293aaae317089ea52f4d/prod/GLM-5.1-SGL-AWQ-TP4.yaml#L45)); the sglang launch command incl. `--log-requests-level 0` is a **literal** block ([yaml:131-155](https://github.com/nearai/cvm-compose-files/blob/c545c95545dba47d8bea293aaae317089ea52f4d/prod/GLM-5.1-SGL-AWQ-TP4.yaml#L131-L155) — cannot be flipped to log requests via env); `VLLM_BACKEND_URLS`, `TLS_CERT_PATH`, `OHTTP_ENABLED` are literal ([yaml:252-254](https://github.com/nearai/cvm-compose-files/blob/c545c95545dba47d8bea293aaae317089ea52f4d/prod/GLM-5.1-SGL-AWQ-TP4.yaml#L252-L254)). Env injection cannot swap the engine, enable request logging, or reroute the core client→nginx→proxy→sglang flow — all covered by `file_sha256`. The reachable content exposure is confined to the proxy's outbound web/tool-search egress.

> **Cross-check with [manifests.md](/manifests/nearai/cvm-compose-files/prod/GLM-5.1-SGL-AWQ-TP4/sha256-eb00b404e3218e2e8c8ab8da5845af10ce79929fd232fe8ac3d2f688582817be.md):** `WEB_CONTEXT_SEARCH_*` and `FUSION_*` are **not in the model node's `allowed_envs`**, so the operator cannot set them without breaking the outer CVM measurement. That reduces the effective invariant to "content capture cannot be enabled without either changing the measurement or leaving a signed, client-verifiable trace."

### HIGH (mechanism) — Launcher auto-updates compose-manager from a MUTABLE tag; cosign gate has an env kill-switch
The launcher polls Docker Hub for `${LAUNCHER_CHANNEL:-latest}` ([`launcher.sh:7`](https://github.com/nearai/compose-manager/blob/9a035b2fadfff19221c3c441c9fa4b7e432919d2/launcher/launcher.sh#L7)), resolves whatever digest `latest` currently points to (`fetch_remote_digest` [`:103-127`](https://github.com/nearai/compose-manager/blob/9a035b2fadfff19221c3c441c9fa4b7e432919d2/launcher/launcher.sh#L103-L127)), and hot-swaps the compose-manager container every 300s — **not pinned to a fixed digest**. cosign verification (`verify_attestation` [`:137-160`](https://github.com/nearai/compose-manager/blob/9a035b2fadfff19221c3c441c9fa4b7e432919d2/launcher/launcher.sh#L137-L160)) is the only gate and is bypassed entirely by **`LAUNCHER_SKIP_VERIFY=1`** ([`:140-143`](https://github.com/nearai/compose-manager/blob/9a035b2fadfff19221c3c441c9fa4b7e432919d2/launcher/launcher.sh#L140-L143)); even when on, it checks only `--certificate-identity-regexp=$COSIGN_IDENTITY` + GitHub OIDC issuer, so any image signed by a CI identity matching the regexp is accepted. **Effective: INCONCLUSIVE from this repo** — `LAUNCHER_SKIP_VERIFY` / `LAUNCHER_COSIGN_IDENTITY_REGEXP` live in the outer CVM app-compose env (not in this checkout; resolved in [manifests.md](/manifests/nearai/cvm-compose-files/prod/GLM-5.1-SGL-AWQ-TP4/sha256-eb00b404e3218e2e8c8ab8da5845af10ce79929fd232fe8ac3d2f688582817be.md), which confirmed the running manager `@6e035c8f…` ≠ the compose-pinned default via the measured `LAUNCHER_CHANNEL`). A client verifier still catches a swap if it pins the expected manager image digest.

### MEDIUM (mechanism) — Running-manager digest is self-reported; action log is a rewritable file
The `compose_manager_started` action records the manager's own image via `docker inspect compose-manager` (`current_image_digest` [`main.rs:2144-2161`](https://github.com/nearai/compose-manager/blob/3d64349a6c71a0711f9dd4f9d2897eefa4a0d8bc/src/main.rs#L2144-L2161), recorded [`:2426-2433`](https://github.com/nearai/compose-manager/blob/3d64349a6c71a0711f9dd4f9d2897eefa4a0d8bc/src/main.rs#L2426-L2433)) — **self-reported by the (possibly swapped) process**; a malicious image could write a known-good digest string. Trustworthiness ultimately depends on the dstack TDX RTMR/event_log independently measuring the container image (not verifiable from this repo). The action log `actions.json` is rewritten wholesale via temp-file+rename (`persist_actions_to_disk` [`:267-271`](https://github.com/nearai/compose-manager/blob/3d64349a6c71a0711f9dd4f9d2897eefa4a0d8bc/src/main.rs#L267-L271)) — **not append-only, not tamper-evident**; integrity vs. attestation holds only because it is hashed into the quote at read-time and the CVM boundary denies the operator write access. For the env-injection leak, rewriting isn't even needed — the env is invisible by design.

### MEDIUM (mechanism) — Tag→content TOCTOU; deploy age-gate is operator-tunable
`validate_tag` resolves the ref via GitHub API and records `commit_sha` ([`main.rs:643-664`](https://github.com/nearai/compose-manager/blob/3d64349a6c71a0711f9dd4f9d2897eefa4a0d8bc/src/main.rs#L643-L664)), but `fetch_github_file` re-fetches content by the **mutable ref** `raw.githubusercontent.com/…/{tag}/{path}` ([`:688-692`](https://github.com/nearai/compose-manager/blob/3d64349a6c71a0711f9dd4f9d2897eefa4a0d8bc/src/main.rs#L688-L692)) — a moved tag between the two calls yields content mismatched to the recorded commit. Low impact: `file_sha256` is computed on the actually-fetched bytes and IS attested. `MIN_TAG_AGE_HOURS` (default 48, [`:677-683`](https://github.com/nearai/compose-manager/blob/3d64349a6c71a0711f9dd4f9d2897eefa4a0d8bc/src/main.rs#L677-L683)) delays fresh tags but is an env knob (`=0` disables it).

### INFO — compose-manager never sees or logs message content (confirmed)
It only fetches compose files (GitHub over TLS), runs `docker compose`, talks to the local dstack socket, and optionally posts to a Slack webhook — never inference bodies. `/compose/logs` runs `docker compose logs` ([`main.rs:1586`](https://github.com/nearai/compose-manager/blob/3d64349a6c71a0711f9dd4f9d2897eefa4a0d8bc/src/main.rs#L1586)), but the engine runs literal `--log-requests-level 0`, so no prompt/response content surfaces. **Egress:** `api.github.com`, `raw.githubusercontent.com` (compose fetch), docker + dstack sockets, optional Slack; launcher → Docker Hub + Sigstore (Fulcio/Rekor) via cosign.

### Verdict: COMPROMISABLE (bounded)
Attestation binds **what compose file is deployed** (`file_sha256`), **which git commit**, and **the manager's self-reported image** — but **not** the per-request `env` overlay that parameterizes that compose. An adversary holding `BEARER_TOKEN` (the operator — exactly the confidential-computing threat actor) can alter deployment behavior invisibly to a remote verifier. **Exact residual attack surface reachable in the GLM-5.1 prod deployment:** (1) redirect the proxy's web/tool-search egress via `WEB_CONTEXT_SEARCH_URL`/`_API_KEY` → exfiltrates prompt-derived queries (not attested, not logged, no allow-list — though gated by `allowed_envs` per [manifests.md](/manifests/nearai/cvm-compose-files/prod/GLM-5.1-SGL-AWQ-TP4/sha256-eb00b404e3218e2e8c8ab8da5845af10ce79929fd232fe8ac3d2f688582817be.md)); (2) substitute the other 20 `${VAR}`s (lower impact — literal endpoints). **What stays protected:** the core plaintext path (nginx→vllm-proxy→sglang), engine image digests, and `--log-requests-level 0` are literals covered by `file_sha256`.

**Recommended fix:** hash the resolved env overlay (keys + value-SHAs) into the `compose_up` `DeploymentAction` so it enters `actions_hash` and the TDX quote; or enforce an injectable-key allow-list.

**Unverified:** whether `WEB_CONTEXT_SEARCH_URL` receives raw content vs. derived queries and what `FUSION_ENABLED` gates (proxy source — see [inference-proxy.md](/images/docker.io/nearaidev/vllm-proxy-rs/sha256-b183677a5d32267539b9b21ec45327a4f3be0a013afeb608c68c4d76e9472e36.md)); whether dstack RTMR/event_log independently measures the manager image; the outer CVM app-compose env (resolved in [manifests.md](/manifests/nearai/cvm-compose-files/prod/GLM-5.1-SGL-AWQ-TP4/sha256-eb00b404e3218e2e8c8ab8da5845af10ce79929fd232fe8ac3d2f688582817be.md)).
