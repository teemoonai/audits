## Verdict: **COMPROMISABLE** by credentialed operator (bounded); no data-plane role; no plaintext exposure

**(a) Can it read plaintext?** Privilege yes; implemented path no. The reads of other containers are `docker compose logs` (any model project, returned to the caller), `docker inspect` including `Config.Env`, and `docker cp -L` of the certbot key. None touches message content unless an engine prints it; none is recorded.

**(b) Can an operator change what runs after measurement?** Yes: the unattested env overlay; any compose file from the configured repo; the unpinned `alpine` runs; the launcher-driven manager swap; and, shown on this page, an unrecorded write of the launcher's image file that bypasses its signature check. New at this build, the record of such changes also expires after seven days.

**(c) Logging / persistence / egress:** nothing sensitive leaves through this binary. Bearer tokens can now persist on the work volume.

**(d) `allowed_envs`:** 18 names. `BEARER_TOKEN`, `LAUNCHER_CHANNEL`, `CM_MIN_TAG_AGE_HOURS` remain the three that matter; none reaches `TLS_*`, `TLS_PLAIN_HTTP`, `ENV_FILES` or `RUST_LOG`.

**What the signed action log commits to at `595123fc`:** the same nine fields per action, canonically encoded and hashed into `report_data[..32]` (`:1240-1246`) — over a list that now holds seven days, the last manager start, and deploy anchors. New action names: `env_override_set`, `env_override_unset` (`file: "env-overrides"`, `file_sha256` of the file, key names in `services`), `launcher_restart` (`file: "launcher-restart-request.json"`, target in `services`). It still does not commit to the env overlay, the compose project, a `dry_run` write, the log reads, or the manager image other than by self-report.

**For the client audit:** the hashing contract and field set are unchanged; three new `action` strings can appear; the list is shorter and its first entries may be months-old anchors followed by a gap. A client that assumed the list is a complete history since boot must stop assuming it.

**Recommended fix:** refuse `file` values that are not compose files the manager itself deployed (or keep fetched files in a subdirectory the launcher never reads), and move the write after the `dry_run` return; have the launcher verify the signature of whatever image it is about to start, not only what it polled; record `project` and an env-overlay hash; keep `compose_manager_started`, `env_override_*` and restart entries beyond seven days or commit to a running hash of the pruned prefix; pin `alpine` by digest; read the certificate from a read-only mount.
