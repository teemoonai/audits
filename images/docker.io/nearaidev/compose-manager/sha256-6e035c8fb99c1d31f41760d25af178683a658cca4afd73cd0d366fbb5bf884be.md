### HIGH (mechanism and effective) — new: two endpoints pull and run a mutable third-party image inside the CVM, one of them with no action-log entry

This build introduces the first code path in which compose-manager **starts a container from an image that appears in no attested manifest and is not pinned by digest**.

`GET /host/cache` runs, for each HuggingFace cache volume:

```
docker_stdout(&["run", "--rm", "-v", &mount, "alpine", "ls", "/v/hub"]).await
```

([`main.rs:3388`](https://github.com/nearai/compose-manager/blob/f91a204549b64218a92c9bada84f8129de3c1f45/src/main.rs#L3388)) — image reference `alpine`, i.e. `docker.io/library/alpine:latest`, **no tag, no digest**. `POST /docker/evict` does the same with a barely-better reference:

```
&["run", "--rm", "-v", &mount, "alpine:3.20", "sh", "-c", script, "sh", &target],
```

([`:3771`](https://github.com/nearai/compose-manager/blob/f91a204549b64218a92c9bada84f8129de3c1f45/src/main.rs#L3771)) — a **mutable tag**, and this one mounts the volume **read-write** and runs `rm -rf` inside it (`evict_subtree` [`:3759-3778`](https://github.com/nearai/compose-manager/blob/f91a204549b64218a92c9bada84f8129de3c1f45/src/main.rs#L3759-L3778)). Neither reference is verified by cosign or anything else before it runs. The registry can serve different bytes under both references with no attestation-visible trace, and the CVM's egress to Docker Hub is the only thing standing between "the operator, or anyone who can influence what that tag resolves to, chooses code" and "that code executes inside the enclave".

**Why the severity is HIGH and not CRITICAL at the deployed config:** the spawned container is an ordinary container. It gets one bind of a named cache volume (model weights) and **no** docker socket, **no** host PID namespace, **no** `SYS_PTRACE` — so it does not inherit compose-manager's privilege and has no route to another container's memory. The read-only mount at `:3388` and the charset-validated, positional-argument target at `:3764-3771` are careful; `model_to_hub_dir` rejects `..`, leading/trailing `/`, `//` and any character outside `[A-Za-z0-9._/-]` ([`:3577-3601`](https://github.com/nearai/compose-manager/blob/f91a204549b64218a92c9bada84f8129de3c1f45/src/main.rs#L3577-L3601)), and `validate_volume_name` refuses anything that is not a plain named volume so a host path cannot be bind-mounted into the deleting container ([`:3609-3620`](https://github.com/nearai/compose-manager/blob/f91a204549b64218a92c9bada84f8129de3c1f45/src/main.rs#L3609-L3620)). The finding is the **unpinned image**, not the argument handling.

**Compounding: `/host/gpu` and `/host/cache` are `GET` routes that record no `DeploymentAction` at all** (`host_gpu` [`:3184-3267`](https://github.com/nearai/compose-manager/blob/f91a204549b64218a92c9bada84f8129de3c1f45/src/main.rs#L3184-L3267), `host_cache` [`:3335-3400`](https://github.com/nearai/compose-manager/blob/f91a204549b64218a92c9bada84f8129de3c1f45/src/main.rs#L3335-L3400) — neither calls `record_action`; routes registered at [`:4005-4006`](https://github.com/nearai/compose-manager/blob/f91a204549b64218a92c9bada84f8129de3c1f45/src/main.rs#L4005-L4006)). So a caller holding `BEARER_TOKEN` can cause `alpine:latest` to be pulled and executed inside the CVM, repeatedly, and **the attested action log will not contain a single entry saying so**. `/docker/evict` does record an action ([`:2404`](https://github.com/nearai/compose-manager/blob/f91a204549b64218a92c9bada84f8129de3c1f45/src/main.rs#L2404) onward).

### MEDIUM (effective) — new: the tag age-gate is 0 at this deployment and is operator-tunable without changing the measurement

The source default is 48 hours (`.unwrap_or_else(|_| "48".to_string())` [`:3852`](https://github.com/nearai/compose-manager/blob/f91a204549b64218a92c9bada84f8129de3c1f45/src/main.rs#L3852)). The measured manifests that run this build set:

```
- MIN_TAG_AGE_HOURS=${CM_MIN_TAG_AGE_HOURS:-0}
```

(`d98a2568…` `docker_compose_file:130`; identically `9385918d…:130`), **and `CM_MIN_TAG_AGE_HOURS` is present in these manifests' `allowed_envs`** (it is absent from the older `fb3d47e5…` / `002b406e…` manifests, which hard-code `MIN_TAG_AGE_HOURS=2`). The check itself is intact — `if tag_info.commit_date > min_age { return Err(… "tag too recent" …) }` ([`:847-853`](https://github.com/nearai/compose-manager/blob/f91a204549b64218a92c9bada84f8129de3c1f45/src/main.rs#L847-L853)) — but with a bound of 0 it never fires. A compose file pushed to `nearai/cvm-compose-files` seconds ago can be deployed immediately, with no soak window in which anyone could notice it. That is a real weakening of the supply-chain gate relative to the hosts running the older builds, it is the *deployed* state rather than a theoretical one, and the operator can keep it at 0 without touching `compose_hash`.

### MEDIUM (mechanism) — new: `dry_run` writes the fetched compose file to disk before the "genuinely read-only" branch, and records nothing

The `dry_run` path is documented as "Genuinely read-only: no action recorded, no deployed_* / deployed.json write, nothing pulled/built/spawned" ([`:651-660`](https://github.com/nearai/compose-manager/blob/f91a204549b64218a92c9bada84f8129de3c1f45/src/main.rs#L651-L660)). The action-log and deployed-state halves of that are true. The disk half is not: `compose_up` fetches the file from GitHub and writes it into `WORK_DIR` at [`:1950`](https://github.com/nearai/compose-manager/blob/f91a204549b64218a92c9bada84f8129de3c1f45/src/main.rs#L1950) (`if let Err(e) = tokio::fs::write(&target_path, &content).await {`) — **before** the `if payload.dry_run` branch at [`:1980`](https://github.com/nearai/compose-manager/blob/f91a204549b64218a92c9bada84f8129de3c1f45/src/main.rs#L1980) returns. A temp env file is likewise written at [`:1954-1961`](https://github.com/nearai/compose-manager/blob/f91a204549b64218a92c9bada84f8129de3c1f45/src/main.rs#L1954-L1961). So a `dry_run` call silently replaces the on-disk compose file that `POST /compose/logs` subsequently uses ([`:2259`](https://github.com/nearai/compose-manager/blob/f91a204549b64218a92c9bada84f8129de3c1f45/src/main.rs#L2259)), with no action-log entry. Bounded: the content must still come from the configured `GITHUB_REPO` at a ref that passes `validate_tag`, and `--dry-run` genuinely applies nothing to any container. Low practical impact, but the code comment overstates the guarantee and the write is unlogged.

### Verdict: COMPROMISABLE by credentialed operator (bounded), with a wider blast radius than the earlier builds

**(a) Can it read plaintext?** Privilege yes; implemented path no. New in this build, it holds every running container's environment in memory during `/host/gpu` and `/docker/evict`, and emits none of it.

**(b) Can an operator change what runs after measurement?** **Yes, by three routes now.** The unattested `env` overlay (CRITICAL/mechanism); the `LAUNCHER_CHANNEL`-driven, reboot-persistent manager swap where the measured digest is a defaultable fallback (MEDIUM here, HIGH in aggregate); and — new — causing an **unpinned `alpine` image** to be pulled from Docker Hub and executed inside the CVM through `/host/cache`, an endpoint that writes **no action-log entry**. The age-gate that used to impose a soak window on new compose files is **0** at this deployment and operator-tunable.

**(c) Logging/persistence/egress:** nothing sensitive leaves. One new egress destination (Docker Hub) implied by the spawned containers.

**(d) `allowed_envs`:** 22 names on `d98a2568…` / `9385918d…`. None flips a content-logging or debug switch. Three matter: `BEARER_TOKEN` (full API access), `LAUNCHER_CHANNEL` (post-measurement swap), and — new on these manifests — **`CM_MIN_TAG_AGE_HOURS`**, which sets the deploy soak window and is 0 by default here. `RUST_LOG`, `LAUNCHER_SKIP_VERIFY`, `CM_GITHUB_REPO` are absent.

**What the signed action log commits to:** `{timestamp, action, tag, commit, file, file_sha256, services, container, image}` per action, canonically encoded and SHA-256'd into `report_data[..32]`. It commits to which compose text was deployed and which commit it claimed to come from. It does **not** commit to the env overlay, does **not** record the manager image except as a self-report, and — new in this build — **does not record `/host/gpu` or `/host/cache` at all**, including the container those endpoints spawn.

**Recommended fix:** pin `alpine` by digest (or drop the spawned-container helpers in favour of reading the volume through the existing mount); record an action for every endpoint that starts a container; hash the resolved env overlay into the `compose_up` action; raise `CM_MIN_TAG_AGE_HOURS` above 0 and remove it from `allowed_envs`.

**Unverified / untraced, stated explicitly:** whether dstack's RTMR/event log independently measures the compose-manager container image; the inner stack this manager deploys (separate manifest pages); the ~2100-line delta was read for routes, subprocesses, egress, disk writes and action-log calls, but the dashboard-facing serialization and the ~750 lines of `#[cfg(test)]` code beyond line 4021 were not line-by-line reviewed; and the fleet-wide count of 4 of 17 hosts comes from the orchestrating census — this review directly read two of those manifests (`d98a2568…`, `9385918d…`).
