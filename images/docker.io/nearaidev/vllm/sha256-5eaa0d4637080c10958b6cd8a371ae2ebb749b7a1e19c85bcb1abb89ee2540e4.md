## Findings

### MEDIUM (deployed: ARMED, fires on an engine-step exception) — engine-crash dump prints every in-flight request's speculative draft token ids to stdout, which the collector ships out of the enclave; the prompt and output histories stay redacted

When `execute_model` raises inside the engine core, the step is wrapped by `log_error_detail` ([`core.py:562-575`](https://github.com/vllm-project/vllm/blob/5df63a7203cdb9328d824a27b682e77c7b9928be/vllm/v1/engine/core.py#L562); call sites [`:672`](https://github.com/vllm-project/vllm/blob/5df63a7203cdb9328d824a27b682e77c7b9928be/vllm/v1/engine/core.py#L672), [`:726`](https://github.com/vllm-project/vllm/blob/5df63a7203cdb9328d824a27b682e77c7b9928be/vllm/v1/engine/core.py#L726), [`:771`](https://github.com/vllm-project/vllm/blob/5df63a7203cdb9328d824a27b682e77c7b9928be/vllm/v1/engine/core.py#L771)) → `dump_engine_exception` → [`dump_input.py:78-79`](https://github.com/vllm-project/vllm/blob/5df63a7203cdb9328d824a27b682e77c7b9928be/vllm/logging_utils/dump_input.py#L78) `logger.error("Dumping scheduler output for model execution: %s", dump_obj)`. Unconditional, no flag, ERROR passes INFO, stdout → `telemetry.infra.near.ai`.

The serializer ([`dump_input.py:19-53`](https://github.com/vllm-project/vllm/blob/5df63a7203cdb9328d824a27b682e77c7b9928be/vllm/logging_utils/dump_input.py#L19)) uses `anon_repr` when a class has one (`:40-41`) and otherwise walks `__dict__` (`:42-47`), printing ints and lists verbatim. `SchedulerOutput` ([`sched/output.py:232`](https://github.com/vllm-project/vllm/blob/5df63a7203cdb9328d824a27b682e77c7b9928be/vllm/v1/core/sched/output.py#L232)) is a plain dataclass with **no `anon_repr` and no `__repr__`** (the only methods in the class are `get_block_ids` and `make_empty`), so its fields are walked. Among them:

```text
    # req_id -> spec_token_ids
    # If a request does not have any spec decode tokens, it will not be
    # included in the dictionary.
    scheduled_spec_decode_tokens: dict[str, list[int]]
```

([`:248-251`](https://github.com/vllm-project/vllm/blob/5df63a7203cdb9328d824a27b682e77c7b9928be/vllm/v1/core/sched/output.py#L248)). The v0.26.0-line page cleared this field because no `--speculative-config` was deployed there. **Here `--speculative-config '{"method":"dspark","num_speculative_tokens":3}'` is deployed**, `dspark` is a standard speculative method ([`config/speculative.py:69`](https://github.com/vllm-project/vllm/blob/5df63a7203cdb9328d824a27b682e77c7b9928be/vllm/config/speculative.py#L69), [`:1164-1168`](https://github.com/vllm-project/vllm/blob/5df63a7203cdb9328d824a27b682e77c7b9928be/vllm/config/speculative.py#L1164) — the draft weights ship inside the target checkpoint), and the scheduler fills the field every step for every running request that has draft tokens ([`scheduler.py:861-872`](https://github.com/vllm-project/vllm/blob/5df63a7203cdb9328d824a27b682e77c7b9928be/vllm/v1/core/sched/scheduler.py#L861) `scheduled_spec_decode_tokens[request.request_id] = spec_token_ids`). Draft tokens are the model's proposed next output tokens (up to 3 per request per step; with DSpark most are accepted and become the reply). So one engine-step exception in any of the eight ranks prints, for every request in that step, request id → up to three model-output token ids, trivially detokenisable. The exposure is bounded (a few tokens per request, crash only), which is why this is MEDIUM and the page is QUALIFIED PASS rather than LEAKS; it is nonetheless a real content sink that did not exist at the v0.26 deployment.

### Verdict: no exfiltration path for chat plaintext at the deployed flags in normal operation; two qualifications

Request/response logging is opt-in and off; the response-body middleware, dev and RL routes, runtime LoRA loading, profiler, tracing, Cohere API and scale-out routes are all gated at process start by values the attested compose leaves unset; there is no runtime logging switch; disk artifacts are config-keyed; the KV cache has no CPU or disk tier; metrics and access logs are aggregate; the five near.ai patches are arithmetic, gating and a weights-only shared table, with no log or file sink, and two of them are dormant at these flags. The crash-path prompt/output token-id leak of v0.12.0 remains closed. The two qualifications are both consequences of *this deployment's* flags on an otherwise unchanged engine: speculative decoding populates a `SchedulerOutput` field the crash dump prints verbatim, and the DeepSeek-V4.1 checkpoint's vision tower makes the request-driven media fetch — unrestricted and redirect-following at these flags — reachable from any chat request, on a process that lives in the CVM's host network namespace.

**Residuals.** Image↔source correspondence for everything but five files rests on labels and the attested build of a Dockerfile that `FROM`s a digest; native components were not read; the proxy may or may not bound the media finding; enclave egress policy and telemetry retention are outside source.
