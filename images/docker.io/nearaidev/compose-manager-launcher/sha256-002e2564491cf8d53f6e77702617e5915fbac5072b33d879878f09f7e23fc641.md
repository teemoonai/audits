## How it picks the manager image

1. **At CVM boot it does not.** dstack starts `compose-manager` from the measured block: the `:94` default (`854e2c6b…`), unless `pre_launch_script` exported `COMPOSE_MANAGER_IMAGE` from `.env.launcher`.
2. **Bootstrap** (`launcher.sh:1072-1118`): copies the bundled compose over `/app/work/compose-manager.yml` (`:1075`); if the state file has no `compose_manager_digest`, seeds it and `.env.launcher` from `docker inspect compose-manager --format {{.Config.Image}}` (`:1093-1106`); otherwise keeps the stored digest and only re-creates a missing `COMPOSE_MANAGER_IMAGE` line (`:1111-1116`).
3. **Every 300 s** (`_poll_compose_manager` `:1128-1190`): `HEAD https://registry-1.docker.io/v2/nearaidev/compose-manager/manifests/${LAUNCHER_CHANNEL:-latest}` (`fetch_remote_digest` `:194-218`, token `:186-192`); the digest must match `^sha256:[0-9a-f]{64}$` (`:222-224`, `:1147`); if it differs from the stored digest: `docker pull repo@digest` (`:1163`), **`cosign verify --certificate-identity-regexp … --certificate-oidc-issuer …`** on that reference (`:242-245`, failure aborts `:1168-1171`), write `COMPOSE_MANAGER_IMAGE=repo@digest` to `.env.launcher` (`:1173`), `docker compose -p dstack -f /app/work/compose-manager.yml --env-file /dstack-env --env-file .env.launcher [--env-file env-overrides] up -d --no-deps compose-manager` (`:1176`, `compose_up` `:289-305`), health check on `/version` (`:1182`), rollback to the previous line on failure (`:1051-1068`).
4. **No remote configuration** beyond the registry tag: no URL other than Docker Hub, the cosign transparency services and `127.0.0.1:8080` is contacted for the manager image. **No digest allow-list**: the only check is the signer-identity regexp.

**State on 2026-11-19.** `compose-manager:latest` and `:prod` resolve to `a0c07308…`, the *base* build; the measured default `854e2c6b…` carries only `staging-20261117-*` tags. So the default channel does not point at the measured manager. A launcher whose stored digest is `854e2c6b…` (fresh state, step 2) would at its first poll install `a0c07308…` — a signed image, so the gate passes — and the CVM would again run a manager its measured document does not name. Both action logs show `854e2c6b…` as the last manager start 14 h and 12 h before capture, so on these hosts either the stored digest is already `a0c07308…` (a state file surviving on the `work` volume would do that) or `LAUNCHER_CHANNEL` is set to another tag. The launcher's state file is not remotely readable; this review cannot say which.

## Verdict: COMPROMISABLE by credentialed operator (bounded); no plaintext exposure of its own

**How it picks the manager image:** the measured default at boot; then whatever digest a mutable Docker Hub tag names, if signed by any workflow of `nearai/compose-manager`; then, on three of four recreate paths, whatever an unverified file on the shared volume names. No digest pin, no allow-list, no remote configuration beyond the tag.

**What moved since the base.** Identity is better: the pinned digest is the signed index and the attestation API answers for it. Scope is wider: two managed containers instead of one, and the second is the node's log exporter. The one integrity control, the cosign gate, is unchanged in strength on the poll path and absent on the paths this build adds. Nothing the launcher does is attested.

**Recommended fix:** verify the signature of the exact reference about to be started inside `compose_up` and `apply_otelcol_target`, not only at poll time; hold `.env.launcher` and the working compose file somewhere the manager cannot write, or validate them as strictly as the overrides file; restrict `otel_image_line` to `OTELCOL_IMAGE_REPO`; pin the manager and collector images in the measured compose instead of defaulting them; have the manager fold launcher outcomes into the attested log; align `latest` with the measured default or stop following a tag.
