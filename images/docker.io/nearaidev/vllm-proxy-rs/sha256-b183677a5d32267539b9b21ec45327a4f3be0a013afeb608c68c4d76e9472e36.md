### MEDIUM-1 (new this run) — Transport-error logs can carry the full upstream URL incl. caller query string (bypasses the repo's own sanitizer)
[`routes/catch_all.rs:186-188`](https://github.com/nearai/inference-proxy/blob/372824b455f0eb4f476cbc744a756add88a8f742/src/routes/catch_all.rs#L186-L188) maps a `reqwest` send error to `AppError::Internal(e.into())` where the forwarded URL is `path_with_query` ([`:153-157`](https://github.com/nearai/inference-proxy/blob/372824b455f0eb4f476cbc744a756add88a8f742/src/routes/catch_all.rs#L153-L157)); [`error.rs:107 error!(error = %e, "Internal server error")`](https://github.com/nearai/inference-proxy/blob/372824b455f0eb4f476cbc744a756add88a8f742/src/error.rs#L107) renders it, and **[reqwest 0.12.28](https://docs.rs/reqwest/0.12.28) `Error` Display includes the full URL with query** (`reqwest src/error.rs:267-269`). The repo *does* treat query params as sensitive (`sanitized_upstream_url_for_logs` [`proxy.rs:154-169`](https://github.com/nearai/inference-proxy/blob/372824b455f0eb4f476cbc744a756add88a8f742/src/proxy.rs#L154-L169); the test [`catch_all_log_sanitization.rs:104-115`](https://github.com/nearai/inference-proxy/blob/372824b455f0eb4f476cbc744a756add88a8f742/tests/catch_all_log_sanitization.rs#L104-L115) asserts `api_key=`/emails never appear) — but both cover only the HTTP-status-error path (`log_upstream_error`), **not connect/timeout/reset transport errors.** Same class: [`routes/ohttp.rs:496 warn!(error = %e, …)`](https://github.com/nearai/inference-proxy/blob/372824b455f0eb4f476cbc744a756add88a8f742/src/routes/ohttp.rs#L496) where the loopback URL embeds the **decrypted** inner path+query. **Impact bound:** chat/prompt content travels in POST bodies, never URLs, so message plaintext is NOT exposed; exposed data is caller-supplied query strings, only on transport failure.

### MEDIUM-2 — Fusion: full decrypted conversation egresses to remote endpoints (opt-in + deployment-gated, acknowledged in code)
[`fusion.rs:829-832`](https://github.com/nearai/inference-proxy/blob/372824b455f0eb4f476cbc744a756add88a8f742/src/fusion.rs#L829-L832): *"SECURITY(V1): E2EE is terminated at this orchestrating proxy. Panel and judge calls forward plaintext over TLS to trusted direct TEE endpoints."* `build_panel_request`/`build_judge_request` ([`:696-750`](https://github.com/nearai/inference-proxy/blob/372824b455f0eb4f476cbc744a756add88a8f742/src/fusion.rs#L696-L750)) clone the post-decryption `messages` and POST them to `{endpoint}/chat/completions` ([`:837-840`](https://github.com/nearai/inference-proxy/blob/372824b455f0eb4f476cbc744a756add88a8f742/src/fusion.rs#L837-L840)) for every panel/judge model. Destinations come from a remote registry (`FUSION_ENDPOINTS_URL`, default `https://completions.near.ai/endpoints`). Weaknesses: (a) `endpoint_base_url` ([`:1355-1366`](https://github.com/nearai/inference-proxy/blob/372824b455f0eb4f476cbc744a756add88a8f742/src/fusion.rs#L1355-L1366)) accepts `http://` registry entries → conversation could travel over plaintext TCP if the registry serves an http domain; (b) one shared `FUSION_INTERNAL_BEARER_TOKEN` is sent to every discovered endpoint. Gating: `FUSION_ENABLED=true` (default false) AND per-request `tools:[{"type":"…:fusion"}]`. teemoon does not enable Fusion.

### INFO-6 — No zeroization of plaintext or derived keys
No `zeroize` in [`Cargo.toml`](https://github.com/nearai/inference-proxy/blob/372824b455f0eb4f476cbc744a756add88a8f742/Cargo.toml)/source. In-memory hygiene only; CVM memory encryption is the mitigating boundary.

### Verified-clean areas (evidence)
- **Logging:** all 186 macro sites reviewed — none takes a body/prompt/completion/decrypted buffer at any level; no `trace!` sites exist; `RUST_LOG` raises verbosity but there is no content-bearing statement to surface. Per-request completion logs carry only `request_id/org_id/workspace_id/model/chat_id/input_tokens/output_tokens/duration`.
- **Upstream error bodies** (vLLM validation errors embed request content): never logged — `log_upstream_error` logs status + sanitized URL + `body.len()` only ([`proxy.rs:188-197`](https://github.com/nearai/inference-proxy/blob/372824b455f0eb4f476cbc744a756add88a8f742/src/proxy.rs#L188-L197)); returned to caller only after `sanitize_validation_errors` strips `'input'/'ctx'/input_value=`; the agent loop **drops upstream bodies entirely** ([`agent_loop.rs:388-392`](https://github.com/nearai/inference-proxy/blob/372824b455f0eb4f476cbc744a756add88a8f742/src/agent_loop.rs#L388-L392) "can contain … user data") and replaces mid-stream error chunks with synthetic sanitized ones.
- **Decryption errors:** uniform `"Decryption failed"` — no oracle, no plaintext echo ([`encryption.rs:409-424`](https://github.com/nearai/inference-proxy/blob/372824b455f0eb4f476cbc744a756add88a8f742/src/encryption.rs#L409-L424)).
- **Persistence:** only in-memory `moka` cache storing `{model}:{sha256(request)}:{sha256(response)}` + signatures keyed by chat id (TTL ~1200s); zero non-test disk writes of content; no log shipper in the image (logs → container stdout; host collection out of scope).
- **Metrics:** labels are method/endpoint/status/reason only; pull-based Prometheus `/metrics`.
- **Env-injectable debug:** full [`config.rs`](https://github.com/nearai/inference-proxy/blob/372824b455f0eb4f476cbc744a756add88a8f742/src/config.rs) sweep — no variable enables content logging/dumps. `DEV`/`GPU_NO_HW_MODE` affect attestation trust, not content flow.

### Verdict: PRIVATE (conditional)
On the default data path — E2EE `/v1/chat/completions` (+ completions/embeddings) without server-side tools — no plaintext reaches any log (at any level), disk, cache, metric, or network destination other than the local engine and the caller, with deliberate, tested discipline (sanitized upstream errors, content-free logs with sentinel tests, dropped error bodies, generic decryption failures). The two content egresses (Brave query; Fusion full-conversation fan-out) are per-request opt-in AND deployment-gated. The one real hygiene gap is MEDIUM-1 (transport-error logging of full URLs with query strings, + the OHTTP inner-path log) — it does not expose message bodies.

**Unverified:** dependency-level TRACE logging (hyper/h2/rustls internals — believed not to log body bytes, not empirically confirmed); the actual deployment env (whether `FUSION_ENABLED`/`WEB_CONTEXT_SEARCH_URL` are set — see [manifests.md](/manifests/nearai/cvm-compose-files/prod/GLM-5.1-SGL-AWQ-TP4/sha256-eb00b404e3218e2e8c8ab8da5845af10ce79929fd232fe8ac3d2f688582817be.md)); host-side log collection + OS core-dump policy; that the deployed image is built from exactly this commit (supply-chain, not source audit).
