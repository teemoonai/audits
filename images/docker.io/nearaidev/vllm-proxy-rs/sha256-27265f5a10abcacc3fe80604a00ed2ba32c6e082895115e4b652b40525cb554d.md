### Verdict: QUALIFIED PASS — the delta adds no plaintext sink; the backend-affinity key is the same salted digest, confined to memory, with strictly fewer sinks than DP affinity; the watchdog change is a boolean classifier; the two client-opt-in egress features carry over unchanged; the running-bytes question is open

On the path every ordinary chat request takes — OHTTP decapsulation → field decryption → salted prefix digest → replica selection → SGLang → encrypted response — this build does not log, persist, cache, or transmit message plaintext anywhere except to the inference engine. The two changes since `101aa49f` were each followed to every sink: PR #227 hashes the conversation prefix with a per-process random salt, stores only the 32-byte digest → replica-index mapping (bounded, expiring, memory-only), and exports only enum/index labels and a count — no log, metric, header, or response carries the digest or its inputs; PR #225 changes only *what arms* the watchdog, via a boolean derived from the SSE event shape, and its error path (disabled at this deployment anyway) logs ids and a fixed string. The mechanical whole-tree sweeps (194 log macros, every metric label, every filesystem call) found no content-bearing sink at any log level.

The verdict is **qualified** rather than PRIVATE for three reasons: **(1)** `web_context_search` and `fusion` are deliberate, client-opt-in paths that move message-derived plaintext (a model-written query; the full conversation) off-box, and their deployed on/off state depends on `${FUSION_ENABLED}`, `${WEB_CONTEXT_SEARCH_URL}` and `${WEB_CONTEXT_SEARCH_API_KEY}` — unattested host-`.env` values this review cannot see, so they are treated as ARMED; **(2)** the catch-all exposes the engines' full route surface to any paying key; **(3)** the attested file that names this digest is not the file that last recreated the proxy service, so this page covers bytes that may not be the ones running — a limit of the attestation surface, stated rather than papered over. **Residuals:** the signed attestation binds image to commit up to trust in GitHub's attestation service and runner (no independent rebuild performed); `attestation.rs` internals, `encryption.rs` correctness, `backend_pool.rs` beyond selection, and the base image were not traced; panic reachability was spot-checked; the engines' behaviour belongs to the SGLang page; the container runs `privileged` as `root` with the dstack socket, so the in-memory confinement claimed for both affinity maps is a claim about this binary, not about the host.
