### Patch A — `streaming-abort.patch` (stream lifecycle; privacy-neutral) — NEW to this build

106 lines, touches `serving_base.py`, `serving_chat.py`, `serving_completions.py`. It adds a `StreamingAbortBeforeFirstChunk(Exception)` (carrying `message`, `err_type`, `status_code`) in `serving_base.py`, and in both serving handlers: when the scheduler aborts a request *before* the first SSE chunk is emitted, it raises the exception with `message = finish_reason.get("message", "Generation aborted.")` and the handler returns `self.create_error_response(e.message, e.err_type, e.status_code)`. The `message` is a **scheduler-generated status string**, not request content, and it is returned to **the same requesting client** — not to any log, file, or sink. No new logging, disk write, socket, or content serializer. This is the same pre-stream-abort behaviour that lived inside the base build's `dsv4-0731-runtime` patch, now split out as its own patch. Privacy-neutral.

### Patch B — `chunked-prefill-admission-reserve.patch` (scheduling; privacy-neutral)

94 lines, touches `schedule_policy.py` and `scheduler.py`. It reads `SGLANG_CHUNKED_PREFILL_ADMISSION_RESERVE` (deployed `=4096`, compose line 159; default `"0"` in the patch, which preserves upstream behaviour), and reserves an aligned slice of the chunk budget so waiting requests are not starved by an in-flight long prefill. The only request-derived value it reads is an **integer length**:

```
first_waiting_req_tokens=( self.waiting_queue[0].seqlen if self.waiting_queue else None )
```

`seqlen` is `len(self.origin_input_ids) + len(self.output_ids)` ([`schedule_batch.py:1201-1203`](https://github.com/sgl-project/sglang/blob/c0b6474b43363c2f4bc60fe3d7817d393fb51d32/python/sglang/srt/managers/schedule_batch.py#L1201)) — a count, not content. The reserve logic is integer arithmetic (`reserve // page_size * page_size`, `min(...)`); it changes *which* request is admitted this pass, nothing about *what* is copied. No logging, I/O, or egress. Same behaviour as the base build's admission-reserve patch, restructured for the nightly (it adds an `AddReqResult.OTHER` early-return when a waiting request's remaining prefill would not fit the reserved budget).

**Neither patch adds a server arg, HTTP route, `ConfigureLoggingReq` field, file write, socket, or serializer of request content.** The engine's privacy surface is therefore the upstream `c0b6474b` surface, evaluated below at the deployed flags.

### Verdict: PRIVATE at the deployed flags — and the two-patch delta is verifiably benign

The bytes are upstream `sgl-project/sglang @ c0b6474b` (a nightly, post-PR-33587) built from source, plus two local patches I recovered from the image and verified by hash against the labels: a chunked-prefill admission-reserve scheduling patch (integer lengths only) and a pre-stream-abort patch that touches the serving path but only returns a scheduler-generated status message to the same client. Neither adds logging, disk, or egress of request content. The reasoning-effort profile that was a local patch in the base `ec518148` build is **upstream** in this tree, so no local patch touches the prompt-encoding path here at all. The new sparse-prefill / compressed-state flags are kernel/dtype selectors with no new disk sink. At the deployed launch flags no plaintext copy is written to any log, file, cache, or network destination in steady state.

The residual posture is the SGLang family posture this repo keeps finding: an unauthenticated `/configure_logging` runtime switch (CRITICAL, deployed ON) that can enable full prompt/output logging and arbitrary-path request dumping with no restart and no attestation-visible event; a watchdog hang-dump of full prompt and output token IDs (HIGH, deployed ARMED) with no flag to disable it; and a container stdout stream shipped verbatim off-box (MEDIUM) with no redaction, which is what turns the first two from in-enclave logs into off-box egress.

### Residuals

1. **`/configure_logging` is unauthenticated** — enables full prompt/output logging and arbitrary-path request dumping at runtime; reachable by any valid API-key holder through the proxy and directly by any container on `dstack_default`. The proxy is a residual, not a mitigation.
2. **The watchdog prompt/output token-ID dump cannot be disabled by configuration** (fires at the 1800s counter-stall).
3. **Container stdout leaves the machine with no redaction stage** (`telemetry.infra.near.ai`, plus the host's measured Datadog agent).
4. **The declared source commit under-describes the running tree** by two out-of-tree patches; recoverable here because the build preserved the `.patch` files and their label hashes. A `sources` pin to `c0b6474b` alone would over-assert.
5. **No signed build attestation** — the from-source GitHub Actions build is trusted, not reproduced; only the base-source + patch bindings are independently checkable.
6. **`--trust-remote-code`** against a pinned checkpoint revision whose Python is unaudited third-party code (the pin bounds it).
7. **The FlashMLA sparse-prefill/compressed-state kernel internals were not read** — traced only to their env declarations and to the absence of any new mounted volume; no request-content sink is possible without a new disk path, and none is mounted.
