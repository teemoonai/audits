# SGLang inference engine (GLM-5.3-Flash, near.ai HiCache W4AFP8 v7 build) — Privacy Audit

> Part of the near.ai inference-path privacy audit. Method: [/notes/method.md](/notes/method.md).

**Image:** `nearaidev/sglang@sha256:fa730e6e62b2ae8058114ce540487ade33ab93bc42b1179ae78edc92bd563fc5`
**Source:** `PierreLeGuen/sglang-upstream` @ `fc91d2403cc210a86bd5fc715c6609f58c932e5a` + seventeen patch files from three `nearai/cvm-compose-files` recipe directories.
**Role:** the inference engine — the one process legitimately entitled to see message plaintext — and, in a second container per CVM, a metrics sidecar (`ghost_aggregator`) that receives keyed digests from the engines. It sits behind `nearaidev/vllm-proxy-rs` behind nginx; engine port 8000 is not host-published but is reachable on the `external: true` shared Docker network `dstack_default` in all four recipes.

**Citations.** Line numbers are those of the rebuilt installed tree — the bytes in the image, which no public commit contains — and are given without links. Files the seventeen-file delta does not touch are byte-identical to the base build, so the base page's post-patch line numbers for them hold; the ones this page rests on were re-read.

**Verdict:** The six new patches add no path by which message plaintext reaches a log, a file, telemetry or the network, at the deployed switches or at any switch I found. What makes the class LEAKS is inherited and unpatched:

1. the **glm47 tool-call parser logs a model-emitted argument value verbatim at WARNING** (MEDIUM, deployed ON) — `function_call/` is byte-identical to the base;

and the paths that keep the rest short of "cannot happen" are also inherited, re-located:

2. **unauthenticated `/configure_logging`** (CRITICAL, deployed ON) — no `--api-key`/`--admin-api-key` in any of the eleven deployed commands;
3. the **watchdog hang dump** (HIGH, deployed ARMED at 1800 s in all eleven);
4. the **request-driven media fetch** (MEDIUM, deployed ON) — no `--allowed-media-domains` in any recipe;
5. two **DEBUG dumps of up to 2,000 characters of model output** on tool-call parse failure (LOW, deployed OFF, level-gated) — unrecorded on the base page, one `log_level` POST away through (2).

New on this page: the **ghost prefix cache** (deployed ON, shared mode, every recipe) hashes every finished request's prompt *and* output token ids into keyed 16-byte page digests and forwards a 1/16 sample over a unix datagram socket to a sidecar in the same CVM — digests, a flag byte and a replica label cross that boundary, nothing else; the **preprocess pool** (deployed ON, 4 workers) moves the chat request and every HTTP header across a fork boundary inside the container and logs timings with a client-supplied request id; the **self-profiler** is OFF everywhere and would print operational counters, not content; **FP8 KV** is a pool-row layout change; the **tool-schema cap** returns the limit's name. Each is rated below.

One deployment fact the recipe headers get right and a reader might not expect: **every v7 engine runs with `--kv-cache-dtype fp8_e4m3`**, including the four `TP2x4` replicas, whose service anchor overrides the bf16 common anchor; and HiCache is **off** on `TP2x4` and `V8KdaCanary` (no `--enable-hierarchical-cache` in the candidate argv) and **on** in `small-models` and `LongContext`.

### LOW (deployed: ON, shared mode in all four recipes) — the ghost prefix cache hashes every finished request's prompt and output token ids into keyed 16-byte page digests and sends a 1/16 sample, with a flag byte and a replica label, over a unix datagram socket to a sidecar that also holds the key; counters only are exported — sink: socket (in-CVM, to a key-holding sidecar container)

The novel plaintext-adjacent path in this build, read in full. The chain, at the installed bytes:

**What is hashed.** `mem_cache/common.py:254` calls `observe_finished_req(req)` on every `release_kv_cache` (19 call sites across the scheduler, batch-result processor, retraction, abort and disaggregation paths). `ghost_cache.py:444–457`: returns unless `SGLANG_GHOST_CACHE=1` (`_ENABLED`, 410); skips unfinished and `FINISH_ABORT` requests (449); on TP rank 0 / PP rank 0 only (`_is_reporting_rank`, 400–407) copies `list(req.origin_input_ids)` and `list(req.output_ids)` (454–455) into a bounded queue (256 entries; a full queue drops and counts, `submit`, 350–354). A daemon thread (`_run`, 356–387) hashes **the whole token sequence, prompt then output**, cut into 64-token pages (`PAGE_TOKENS = 64`, 52): `_chain` (232–243) packs each page's ids as int64 and computes `blake2b(prev + page, digest_size=16, key=key)` (241) — a 16-byte keyed digest per page, chained so each digest commits to every preceding token. The key is 32 bytes (`KEY_BYTES`, 73): `os.urandom(32)` per process (224), or in shared mode the contents of `/ghost/key` (423–426).

**The sample rule.** `_tracked` (245–246): a page is tracked iff the low 32 bits of its digest are `0 mod 16` (`SGLANG_GHOST_CACHE_SAMPLE=16`). Hashing covers every page (the chain needs it); tracking, the LRU and forwarding cover one page in sixteen, chosen by the keyed digest itself, so the sample is not under a client's control.

**What crosses the socket.** `encode_records` (109–116): a 11-byte header (`GHC1`, sample, label length, record count — `_WIRE_HEADER`, 75), the replica label (≤255 bytes, the env value `r1a`…), then 17 bytes per tracked page: one flag byte (1 = prompt page, 0 = output page) and the 16-byte digest (`_WIRE_RECORD`, 76). Up to 3,500 records per datagram (`MAX_RECORDS_PER_MESSAGE`, 119). No request id, no token ids, no text, no timestamps, no lengths — though the record count per datagram discloses roughly how many 1,024-token units a request spanned, one request per burst. Sent non-blocking (`sock.setblocking(False)`, 315; `sendto`, 368) to `SGLANG_GHOST_CACHE_SOCKET` = `/ghost/aggregator.sock`; an `OSError` drops and counts (369–370).

**The key file.** `load_shared_key` (79–104): if `/ghost/key` is absent, write 32 random bytes to a private temp file created `O_EXCL` with mode `0600` (86–88) and `os.link` it into place (93), losing the race harmlessly; then read until 32 bytes are present. Created by whichever engine starts first, in the engine's uid. The volume is tmpfs, 1 MiB, `mode=0700`, mounted only by the engines and the aggregator. The key is never logged (the startup INFO at 432–439 prints `key=shared` or `per-process`, the sample, the page cap and `replica -> socket`) and never exported.

**What the aggregator keeps and exports.** `ghost_aggregator.py`: binds the datagram socket, `chmod 0o660` (122–123), `start_http_server(port)` from `prometheus_client` (124) — on all interfaces of the container, reachable on `dstack_default`, no `ports:` mapping. Per message: `decode_records`, a sample-rate check, then `PoolAccounting.process` (73–94), which touches each digest in a `StackDistanceLRU` capped at `--max-pages` 4,000,000 digests (59; older ones dropped on compaction) and records a per-replica bit mask in `seen_by` (60, 91). Exported, all per `model_name`/`replica` with fixed label values: `sglang:ghost_pool_lookup_tokens_total`, `…reused_tokens_total{within}`, `…other_replica_only_tokens_total`, `…messages_total`, `…bad_messages_total`, `…tracked_pages` (104–114). The engine side exports `sglang:ghost_{requests,dropped_requests,prompt_tokens,actual_cached_tokens,lookup_tokens,reused_tokens{within},reused_age_tokens{within_s},forward_dropped}_total` and `ghost_tracked_pages` (320–343) — token *counts*, scaled by 16. Digests leave neither process. Logs: aggregator one INFO at start (125); `logging.basicConfig(INFO)` (158); nothing per message.

**Reversibility.** A 128-bit keyed BLAKE2b over 512 bytes of token ids is not invertible without the key. **With** the key — which exists only in `/ghost/key` and in the two processes' memory, inside the CVM — a holder can *confirm* a guessed page, but only if they also know every preceding token of that request (the chain), so the first page of a prompt is checkable against a dictionary of candidate 64-token openings (a shared system prompt, a template) and later pages only after the earlier ones are known. That is a membership oracle for guessable prefixes, not a decoder. The record flag byte and the per-request burst additionally reveal, to a socket observer in the same CVM, that *some* request of about N×1,024 tokens finished on replica r.

**Rating.** LOW, not INFO, because a request-derived artifact leaves the engine process for another container, and that container is the wrong recipient to be key-blind: `glm53-ghost-aggregator` mounts the same `ghost` volume that holds `/ghost/key`, runs with no `user:` like the engines, and so holds both the digest set (up to 4,000,000 sampled pages, for its process lifetime) and the key — it could confirm an exact guessed prompt prefix, page by page, for anything it has seen. Not higher, because the sidecar is this same image in the same CVM under the same uid, nothing decodes to plaintext without a full-prefix guess, and only counters leave the CVM — the same reasoning the base page applied to `/dev/shm` segments reachable across containers. The same mechanism on the v6 and v8 siblings carries the same rating.

**What would change the rating:** moving `/ghost/key` to a persisted or host-shared volume; exporting digests or per-request records; lowering `SAMPLE` to 1 does not change the kind, only the volume. The recipe comment's "tokens never leave the engine" is accurate at these bytes.

### Verdict: LEAKS — the base's one leak, carried through six more patches that add none of their own

This image is the `47aff791` build plus six patches and a wheel, and I could check that from the recipe's own pins: every patch hash, every manifest before/after hash and the workflow's three pinned files match, the replayed tree differs from the base build's in exactly seventeen files, and I read all seventeen. What I did not do, and the base page did, is pull the layers from the registry; the page says so.

The patches add observability (a keyed digest cache with a sidecar, eviction counters, an opt-in profiler), robustness (a process pool with a deadline, a schema size cap) and a denser KV encoding. I read every line that logs, writes, forks, sends or reads the environment. The ghost cache is the one that handles token ids outside the request path, and what it lets out of the engine is a keyed 16-byte digest of one page in sixteen, to a process in the same CVM that holds a key no one else can read; its counters are counts. The pool copies the request to child processes and logs timings. The profiler is off, and on it would print numbers. The cap returns the name of the limit. None of that is a sink.

What the patches do not remove is everything the base page found: the glm47 parser still logs a model-emitted argument at WARNING in normal operation, and all four recipes still ship that line off-box — deployed ON, which is why the class is LEAKS. `/configure_logging` is still one unauthenticated POST away from verbatim prompt logging. The watchdog still dumps the in-flight batch's token ids on a hang. The media fetch still has no allowlist. And `/dev/shm` is still shared with the host IPC namespace.

### Residuals

1. **The glm47 `{value}` warning** has survived five attested rebuilds of a recipe directory that exists to patch this tree.
2. **`/configure_logging` is unauthenticated**; reachability from outside the CVM depends on `vllm-proxy-rs@d61357da…`, a different image.
3. **The registry layers of this digest were not compared with the reconstruction**; the base page's result for `47aff791` is relied on by method.
4. **The ghost sidecar holds both the key and the digest set**, a confirmation oracle for guessable 64-token prompt openings — to an actor inside that container or the CVM. Keep the key on in-memory storage mounted by these three containers only; a key the sidecar cannot read would drop this to INFO.
5. **Client-supplied `rid` reaches stdout** on slow or timed-out preprocessing, and the watchdog dump has always printed it; `rid` is the caller's identifier, not the message, but a caller can put anything there.
6. **HiCache's host tier and the FP8 row kernels** are on the request path and not line-reviewed by any page in this repo.
7. **The eleven engines run four more processes each** (zygote + workers) that hold a copy of one request at a time; a process-wide crash diagnostic would include them.
8. **The `TP2x4` and `V8KdaCanary` files carry a dead common anchor** (bf16, HiCache on) that no service uses; a future edit that re-points a replica at it changes the KV encoding and turns HiCache on without touching this image. A recipe-page concern, recorded here because the brief for this review described those replicas by that anchor.
