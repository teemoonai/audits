## Verdict

**LEAKS**, narrowly, and for one reason where the predecessor had two.

Identity is the strongest class here: a signed attestation, and beneath it every file the 17 patches touch compared byte for byte with a replay of the hash-pinned series. What is not verified is upstream's own base image, and upstream v0.5.23 was swept for log sinks, not read.

Against the image it replaces on these three services, this build fixes what that page found in the LLM engine. The tool-call parser both Qwen models use printed the model's argument values into a log that leaves the CVM; it now prints their lengths, and I ran it to see. The watchdog, armed at 300 seconds, would have put a whole batch's prompts in the same log; it now prints two numbers per request. The DEBUG and error lines that carried model output or a client's schema carry counts and type names. Local file reads through media inputs are refused. For the two Qwen services I found no line at the deployed flags that copies prompt text, reply text or token ids anywhere in normal operation.

What it did not change is the posture around the engine. `/configure_logging` is still one unauthenticated POST away from verbatim prompt logging and request pickling. Engine stdout still leaves the CVM unredacted. A grammar rejection would still log the reply's token ids and the client's schema; the two ways the base addendum could name for reaching that line on the old image are closed by patches in this series, and I still found no request that fires it.

The class comes from FLUX. That service is a different program inside the same image; it saves each generated image, and each image sent in for editing, to its container's disk by default, and the recipe does not turn that off. The two diffusion patches in this series tighten where that program will fetch from and which request fields it accepts, and neither touches the output path. The files stay inside the CVM, and two flags on one service end it.

Not PRIVATE: a file receives model output, and on the edit route user input, at the deployed flags without any operator action. Not INCONCLUSIVE: identity and source are established, and the image is running.
