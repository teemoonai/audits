# SGLang inference engine (GLM-5.3-Flash, near.ai v0.5.23 build) — Privacy Audit

### LOW (deployed: ON) — the ghost prefix cache sends keyed digests of each finished request's prompt and output token pages out of the engine process to a sidecar container, and the key sits on the volume both share — sink: egress (unix socket to a non-model process, inside the CVM) / telemetry (aggregate counters)

New in this build (patch 20) and on in all 25 service blocks.

- Hook: `mem_cache/common.py:406` calls `observe_finished_req(req)` from `release_kv_cache` (`:401`). With `SGLANG_GHOST_CACHE=1` (`observability/ghost_cache.py:411`), for every finished, non-aborted request on TP rank 0 it copies `req.origin_input_ids` and `req.output_ids` to a queue (`:445-456`).
- A background thread cuts prompt-then-output into 64-token pages (`:52`, `:255`) and chains keyed BLAKE2b over them, 16-byte digests, each covering every token before it (`:232-243`, the hash at `:241`). Pages are sampled by digest value, 1 in 16 (`:245-246`).
- With `SGLANG_GHOST_CACHE_SOCKET` set, the sampled digests, a prompt/output flag bit each and the replica label are sent as datagrams to `/ghost/aggregator.sock` (`:365-370`; wire format `:74-76`, `:109-116`). **This is the data that leaves the engine process.** No token ids and no text are in the message.
- The key: 32 random bytes in `/ghost/key`, created `0600` by the first replica (`:79-106`), on the `ghost` tmpfs volume (`:2345-2350`), which the aggregator container also mounts read-write (`:1397-1398`).
- The aggregator (`ghost_aggregator.py`) binds the socket (`:118-123`), keeps a pooled LRU of digests in memory, serves Prometheus counters on port 9464 (`:105-114`, `:124`) and logs one startup line (`:125`). Engine-side metrics are counters and one gauge labelled by model name and bucket (`ghost_cache.py:320-343`).

**What this is and is not.** It is not a copy of plaintext: a digest cannot be inverted. It is prompt-derived data outside the engine process: whoever holds the key and the digests can test a guess — "did some request begin with exactly these N x 64 tokens" — and can see when two requests, on any replica of the CVM, share a prefix. The first pages of most requests are a system prompt and are guessable; later pages are chained over everything before them, so a guess must get the whole prefix right. Requests shorter than 64 tokens produce no digest. The aggregator runs with `cap_drop: [ALL]` and no GPU, but it is a second process holding per-request derivatives, and it is a different image digest than the one reviewed here. Rated LOW and metadata-class; it does not set the class. (Guessability is reasoned from the construction, not demonstrated.)

**Off switch:** unset `SGLANG_GHOST_CACHE`, or keep it and drop `SGLANG_GHOST_CACHE_SOCKET` and `_KEY_FILE` — then the key is per-process random and nothing but counters leaves the engine (`:224`, `:313-315`, `:429-430`).

## Verdict

**PRIVATE at the deployed flags** — with the qualifier this repo attaches to every sglang engine page that meets the condition: *at the deployed flags, and not "cannot happen"*.

This is a new engine tree, not a patch on the old one. I could check from bytes that the image is upstream's v0.5.23 image plus five layers, and that every source file those layers change is what the published, hash-pinned patch series produces. I could not check upstream's own image beyond its labels and unsigned provenance, and I did not read upstream v0.5.23 line by line; the review of that tree is a targeted one, and the *Not traced* section says where it stops.

Within that scope: request logging is off and pinned to its safest level in all nine recipe revisions; no file, exporter or outbound client receives message content at the declared flags; the three new diagnostics that are on — the stall dump, the preprocessing pool, the tier metrics — carry stacks, sizes and counts.

What the new base did not fix is the old posture. `/configure_logging` is one unauthenticated POST away from verbatim prompt logging and request pickling; the patch whose name suggests otherwise redacts keys and adds no check, and no recipe configures a key for it to redact. The watchdog still prints the in-flight batch's token ids on an 1800 s hang. The media fetch has no allowlist. Engine stdout leaves the CVM unredacted. Patch 15 is a real narrowing — schemas, tool-argument values and media URLs no longer appear in the lines it rewrites — but it rewrites specific lines, not the logging surface.

One thing is new and deserves a decision rather than a severity: the ghost prefix cache. It sends keyed digests of request token pages to a second container and keeps the key where that container can read it. No text and no token ids leave the engine, so it does not make this page LEAKS. It is nonetheless the first flow in this image family where something computed from every request's content leaves the engine process by design.

Not LEAKS: no sink receives plaintext or token ids at the deployed flags in normal operation. Not COMPROMISABLE: an unauthenticated engine route has consistently been recorded as a residual under PRIVATE on this ref. Not QUALIFIED PASS, which this repo uses for proxies and management services.
