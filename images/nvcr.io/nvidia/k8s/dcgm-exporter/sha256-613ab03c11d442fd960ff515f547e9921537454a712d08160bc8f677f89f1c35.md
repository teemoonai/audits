## verdict: QUALIFIED PASS — telemetry-not-content at deployed config; the base page's unauthenticated pprof surface is closed upstream; GPU-privileged; bytes pinned but no build provenance at all this time

At the attested configuration this container collects **49 aggregate GPU counters, enums, codes and hardware-identity labels and nothing else**, from a field list that is inline in the attested manifest, and serves them pull-only on a port that is not published to the host. Every label value was traced to a numeric code, an enum name, or a driver/VBIOS string; DCGM's free-text health message is available to the code and not emitted. There is no field in DCGM that returns GPU memory contents; there is no outbound TCP client anywhere in the exporter; the one new HTTP client is a unix-socket runtime-API reader behind a flag that is off and a socket that is not mounted; there are no volumes, no shared PID namespace and no `SYS_PTRACE`. **No plaintext path was found**, and the base page's one real finding — unauthenticated `/debug/pprof/*` — is retired at this tag by a flag that defaults off and cannot be enabled without auth.

Why QUALIFIED rather than PRIVATE:

1. **Privilege.** `SYS_ADMIN` + nvidia runtime over all eight GPUs on which plaintext is computed, running as `root:root`, with two shells in a "distroless" image. Justified by the profiling fields; still the most privileged sidecar in the recipe, kept in scope for exactly that reason.
2. **The source→bytes link is open, and wider than on the base.** The digest pins *which* bytes; the registry mapping pins NVIDIA's label; nothing — not even an internal commit reference — binds these bytes to the public tree this page read. The image predates the public tag by seven days.
3. **A closed-source DCGM/NVML core** does the actual GPU reads.
