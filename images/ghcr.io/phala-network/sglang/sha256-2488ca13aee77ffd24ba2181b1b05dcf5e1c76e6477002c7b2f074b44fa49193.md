# SGLang inference engine (GLM-5.3-Flash, Phala fork) — Privacy Audit

> Part of the near.ai inference-path privacy audit. Method: [/notes/method.md](/notes/method.md).

**Image:** `ghcr.io/phala-network/sglang@sha256:2488ca13aee77ffd24ba2181b1b05dcf5e1c76e6477002c7b2f074b44fa49193` (r12, 2026-08-28), plus the in-enclave `protocol.py` patch.
**Source:** `Phala-Network/sglang` @ `26f67bd9fbbb07e4f14a66f64b0a623ef1c55cd9` for all but six files; those six from Phala layers (digests below).
**Role:** the inference engine — the one process legitimately entitled to see message plaintext. It sits behind `nearaidev/vllm-proxy-rs` (the E2EE/OHTTP terminator, `OHTTP_ENABLED=true`, recipe line 363) behind nginx; engine port 8000 is not host-published but is reachable on the `external: true` shared Docker network `dstack_default` (recipe lines 527–530).

**Verdict:** At the deployed launch flags, request logging is off and pinned to its safest level, request/crash dumping is off, no engine telemetry is emitted, Prometheus labels are content-free, the multimodal embedding and preprocess caches are in-memory, and nothing request-derived is written to the mounted volumes. But one deployed-ON path writes model output to the log in normal operation:

1. the **glm47 tool-call parser logs a model-emitted argument value verbatim at WARNING** when a numeric-typed parameter is not numeric (MEDIUM, deployed ON) — a fragment of the response, on a routine model formatting slip, with no flag to suppress it;

and three paths keep the rest short of "cannot happen":

2. an **unauthenticated `/configure_logging` endpoint** (CRITICAL, deployed ON) — one POST turns on verbatim prompt+output logging and arbitrary-path request pickling, no restart;
3. a **watchdog hang-time dump** (HIGH, deployed ON) — full prompt and output token IDs of the in-flight batch at ERROR on an engine hang, undisableable, armed at the explicitly set **1800 s**;
4. a **request-driven media fetch** (MEDIUM, deployed ON) — GLM-5.3-Flash is multimodal (image + video), the allowlist mechanism now exists but defaults to empty, so any host is fetched; `file://` and absolute paths are still read.

The amplifier: this recipe runs its own `otelcol-contrib`, which ships engine stdout verbatim to `https://telemetry.infra.near.ai` with no redaction stage (recipe lines 495–533, 552, 759–768, 796–799, 813–816). Finding 1 therefore terminates off-box, which is what makes the class LEAKS rather than PRIVATE-with-residuals.

### Verdict: LEAKS — narrowly, and otherwise private at the deployed flags on a registry-verified patchwork

At the flags actually deployed, I found one path by which response content reaches a log in normal operation: the deployed glm47 tool-call parser logs a model-emitted argument value verbatim at WARNING whenever a numeric-typed parameter is not numeric — a routine LLM formatting slip, no attacker, no config change, no flag to suppress it — and this recipe's own collector ships that line to `telemetry.infra.near.ai` with no redaction. The blast radius is one argument fragment per occurrence in tool-using traffic, which is why the severity is MEDIUM and not HIGH; it is still a deployed-ON write of plaintext to an off-box sink, which is why the class is LEAKS and not PRIVATE.

Everything else is the fleet's known posture, re-derived at these bytes: request logging off and pinned to its safest level (genuinely consumed on this path), request/crash dumping off, no engine telemetry, content-free metrics, in-memory multimodal caches, nothing request-derived on the persisted volumes, `--trust-remote-code` not set, the in-enclave patch clean. And "off" is not "cannot happen": the **unauthenticated `/configure_logging`** switch is present and unchanged (one POST turns on verbatim prompt+output logging and arbitrary-path pickling), the **watchdog dump** is undisableable at 1800 s, and the **media fetch** — live because GLM-5.3-Flash is multimodal — has an allowlist mechanism that defaults to empty and still reads local files.

On identity: this page is unusual in that the sglang python tree was verified from the registry layers rather than trusted from a label — and that verification is exactly what exposed the image as a twelve-layer patchwork over an unknown-commit base, with four source commits that are not public and a bundled patched transformers whose commit cannot be recovered. The reviewed bytes are the deployed bytes for the python tree; below it the identity is Phala's word.

10. **Four of the Phala source commits are not public** (`a04636eb`, `cd10a977`, `4fb9ff24`, `f03aade7`); their final bytes were reviewed, their history was not.
