## Results

### os_image_hash - recomputed from the release asset

The measurement rule is unchanged, `mkimage.sh:101-102`:
```
sha256sum ovmf.fd bzImage initramfs.cpio.gz metadata.json > sha256sum.txt
sha256sum sha256sum.txt | awk '{print $1}' > digest.txt
```
i.e. **os_image_hash = sha256(sha256sum.txt)** over firmware, kernel, initramfs and `metadata.json`. I extracted the tarball into a fresh directory and ran `shasum -a 256 ovmf.fd bzImage initramfs.cpio.gz metadata.json`: the output is **byte-equal** (`cmp`) to the shipped `sha256sum.txt` (`983aa76e...` ovmf.fd, `400428f0...` bzImage, `0037a55e...` initramfs.cpio.gz, `a29b7b4b...` metadata.json), and `sha256(sha256sum.txt)` = **`91fd5d69ccee3e5ea4f2aeb8c9b632c4358c4ecfc29ba1aa6fb1e402af209829`** = the shipped `digest.txt` = the `dstack-nvidia-0.5.12` row of the release notes = the `os_image_hash` the orchestrator's capture reports on all eleven hosts. The tag `v0.5.12` resolves to `7f7b2762` (refs API), `metadata.json.git_revision` is `7f7b2762`, and the trees API at that commit returns the submodule pins in the identity table - `dstack` moved to `43f69f41` (= dstack tag `v0.5.12`), the other six are byte-for-byte the v0.5.11 page's pins.

The 465 MB rootfs is not hashed directly but **bound transitively**, and on this page the binding was closed: `mkimage.sh:82` puts `dstack.rootfs_hash=$ROOT_HASH dstack.rootfs_size=$DATA_SIZE` into the kernel cmdline that `:88` writes into `metadata.json`, and the initramfs enforces it at boot (`meta-dstack/recipes-core/images/dstack-initscript/init:40`: `veritysetup open ${ROOT_DEV} rootfs ${ROOT_DEV} "${ROOT_HASH}" --hash-offset="${DATA_SIZE}" --panic-on-corruption`, then `:43` mounts the mapper device as squashfs and `:53` `switch_root`). ### Verdict: QUALIFIED PASS at measured configuration

At the measured configuration the upstream 0.5.12 production guest has **no active plaintext sink**, on all eleven hosts: the facilities the v0.5.11 page cleared are cleared again here against the shipped v0.5.12 bytes - no login, getty, ssh, capture or debug tooling; no telemetry or log shipper; a RAM-only journal; container stdout under `json-file` on a KMS-keyed LUKS2/ZFS disk; the host-shared channel read-only at both ends and now `nosuid,nodev,noexec` with byte-bounded copies; secrets on tmpfs and now owner-only; the container-log route unregistered by `public_logs: false`; `gateway_enabled: false` removing the tunnel, its registration egress and its filter as one unit; the NVIDIA runtime's log output never having been a console or host sink at either level. Every hunk of the delta is a hardening of a boundary (host share, env file, secret modes, LUKS header, KMS identity, agent availability, initramfs mounts, verity policy) or touches no guest byte (CI, host-side build script). The rootfs is now bound to the digest by a recomputed verity root, not only by the build's design. Every host- or operator-flippable switch that changes guest behaviour lands inside a measurement.

**Why not PRIVATE:** the same three reasons as v0.5.11, each re-verified at these bytes and now applying to the whole fleet: (1) an **armed crash path** - `CONFIG_COREDUMP=y`, no handler, unlimited core rlimit from both runtime units, default `core_pattern` - persists a crashing engine's memory to the in-enclave data disk with no flip and no attestation trace; encrypted at rest and off the network, but a plaintext copy on disk that in-guest root can read; (2) the kernel ships **no LSM** (`CONFIG_SECURITY` unset), so the substrate offers the measured scripts and the ptrace-capable control plane `/proc/kcore`, kprobes/uprobes/BPF and unsigned modules with nothing but uid checks in the way - the OS does not mitigate the manifest layer's findings, it hosts them; (3) the prod image carries `curl`, `rsync`, `python3`, busybox `nc`/`telnet` - exfiltration primitives whose only gate is the measurement of the scripts that could call them.

**Residuals (outside this image or unverified):** reproducibility is designed for but was not exercised, and the `bzImage` changed without a recipe change (above); the Linux kernel, poky/meta-oe/meta-virtualization sources (docker, containerd, runc), sysbox, EDK2, the NVIDIA 595.58.03 blobs and the `safe-write` crate were not line-audited; the host serial console and logfile remain a standing host-readable channel for service logs; the host VMM's `readonly=on` for the 9p share is host code, backstopped by the guest's own `ro,noexec` mount and unmount.
